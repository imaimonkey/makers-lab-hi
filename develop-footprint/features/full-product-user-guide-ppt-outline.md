# 01. 표지

## 화면 제목

**신규위험 전략 워크벤치 사용 설명서**

### 부제

신호를 발견하고, 위험 후보를 비교하고, 보험 관점의 검토 리포트로 연결하는 방법

### 화면에 넣을 짧은 문구

`신호 → 후보 → 평가 → 리포트`

### 발표자 설명

이 서비스는 아직 보험상품을 판매하는 화면이 아닙니다. 산업 변화, 기술 변화, 법률 변화, 현장 요청처럼 흩어진 신호를 모아 보험 관점에서 검토할 수 있도록 돕는 내부 프로토타입입니다.

### 캡처 권장

전체 서비스의 대표 화면 또는 위험 레이더 첫 화면

# 02. 이 서비스는 무엇을 해결하나요?

## 핵심 문구

**흩어진 위험 신호를 보험상품 검토가 가능한 구조로 바꿉니다.**

### PPT 본문

- 뉴스·보고서·법령·시장자료에서 새로운 변화를 발견합니다.
- 여러 자료에 반복해서 나타나는 위험을 후보로 묶습니다.
- 시장성, 손해 규모, 보험사고 성립 가능성, 법률·규제 부담을 비교합니다.
- 기존 보험으로 보장되는 부분과 비어 있는 부분을 확인합니다.
- 마지막으로 추가 확인이 필요한 과제와 상품화 검토 방향을 리포트로 정리합니다.

### 비전공자 용어 설명

**신규위험**이란 기존 보험으로 충분히 설명하기 어렵거나, 기술·사회·법률 변화로 새롭게 커지는 위험을 뜻합니다.

### 발표용 한 문장

“이 화면은 아이디어를 바로 상품으로 확정하는 도구가 아니라, 상품 검토를 시작할 만한 위험을 근거와 함께 좁혀가는 도구입니다.”

# 03. 전체 업무 흐름

## 화면 제목

**신호에서 의사결정까지 4단계로 연결됩니다.**

### 화면 구성

`신호 수집` → `위험 후보화` → `보험 관점 평가` → `종합 리포트`

### 각 단계 설명

1. **신호 수집**: 뉴스, 정책, 법령, 시장자료, 고객·영업 현장의 반복 요청을 모읍니다.
2. **위험 후보화**: 여러 신호를 하나의 위험 주제로 묶고 발생 구조와 손해 유형을 정의합니다.
3. **보험 관점 평가**: 기존 보험 연결, 보장 공백, 책임 주체, 손해 측정 가능성을 확인합니다.
4. **종합 리포트**: 상품화 판단에 필요한 근거, 질문, 제안, 추가 검토사항을 한 문서로 정리합니다.

### 기억할 점

한 번의 AI 분석 결과가 최종 결론이 아닙니다. 각 단계에서 원문과 담당자 검토가 이어져야 합니다.

| 모드 | 누가 사용하나요? | 핵심 목적 | 대표 결과 |
| --- | --- | --- | --- |
| **실무자** | 위험·상품개발 담당자 | 후보를 비교하고 상품화 검토 | 위험 후보, 상세 평가, 종합 리포트 |
| **개발자** | AI·데이터·서비스 개발 담당자 | 분석 프롬프트와 결과를 테스트 | 단계별 AI 분석 결과, 저장 데이터 |
| **영업부서** | 영업점·법인영업·GA 등 | 현장 위험 신호와 상품 아이디어 접수 | 검토 대기 현장 리포트 |

### 발표용 주의사항

모드는 사용자의 역할에 따라 화면과 목적이 달라집니다. 고객 모드의 입력을 실무자 위험 후보로 자동 승격하지 않으며, 영업부서 입력도 사람이 검토하기 전에는 신규위험으로 확정하지 않습니다.

# 05. 공통 화면 사용법

## 상단과 좌측 메뉴 읽기

- **좌측 메뉴**: 현재 모드에서 사용할 수 있는 핵심 화면으로 이동합니다.
- **상단 모드 전환**: 실무자·개발자·영업부서·개인 고객 화면을 바꿉니다.
- **현재 위치 표시**: 선택된 메뉴가 흰색 또는 강조 상태로 표시됩니다.
- **통합 검색 영역**: 신규 위험·기사·후보 검색 연동을 위한 영역입니다. 구현 상태에 따라 검색 기능이 제한될 수 있습니다.
- **하단 안내**: 이 서비스가 내부 콘셉트·프로토타입임을 확인합니다.

## 공통 버튼 읽기

- `위험 상세 →`: 선택한 후보의 발생 구조와 보험 연결을 확인합니다.
- `종합 리포트 →`: 여러 검토 결과를 의사결정 문서 형태로 확인합니다.
- `원문 →` 또는 `원문 확인`: AI 요약의 근거가 된 공식 자료를 직접 확인합니다.
- `추가 확인 필요`: 현재 데이터만으로 결론을 내리기 어려운 항목입니다.

# 06. 실무자 모드 개요

## 화면 제목

**실무자 모드에서 후보를 발견하고 검토합니다.**

### 메뉴 4개

1. **위험 레이더**: 전체 위험 신호와 우선 검토 후보를 한눈에 봅니다.

`위험 레이더`에서 관심 후보 발견 → `위험 탐색`에서 후보 비교 → `위험 상세`에서 구조 확인 → `종합 리포트`에서 의사결정용 정리

# 07. 위험 레이더(대시보드)

## 화면 목적

**최근에 들어온 위험 신호를 한눈에 보고, 우선 검토 후보를 빠르게 파악하는 시작 화면입니다.**

### 주요 영역

#### 1) 핵심 KPI

최근 30일 기준 신규 위험, 검토 후보, 법·규제 변화, 유입 신호 등을 요약합니다.

#### 2) 상품화 우선 검토 TOP 5

종합점수가 높은 후보 5개를 보여줍니다. 왼쪽 후보를 누르면 오른쪽 요약 카드가 바뀝니다.

#### 3) 신규 위험 후보

최근 포착된 대표 후보를 보여주며 `위험 상세`로 이동할 수 있습니다.

#### 4) 주요 법·규제 변화

법률·규제 변화 후보를 별도 묶음으로 보고, 전체 보기를 통해 위험 탐색의 법률 카테고리로 이동합니다.

#### 5) 보험시장 상품개발 동향

국내 보험 인사이트, 글로벌 보험 인사이트, 최근 출시 상품 등 상품개발 참고 자료를 확인합니다.

#### 6) 스크랩한 종합 리포트·핵심 위험 키워드

저장해 둔 리포트와 분야별 키워드로 다시 탐색합니다.

### 사용법

1. TOP 5에서 후보를 선택합니다.
2. 오른쪽 카드의 시장성·종합점수·요약을 확인합니다.
3. 더 자세히 보려면 `위험 상세`, 의사결정 문서로 보려면 `종합 리포트`를 누릅니다.

### 용어

**KPI**는 핵심성과지표라는 뜻으로, 화면의 현황을 숫자로 요약한 값입니다. **TOP 5**는 전체 후보 중 우선 검토 대상으로 표시한 상위 5건입니다.

### 캡처 권장

TOP 5와 오른쪽 후보 요약 카드가 함께 보이는 화면

# 08. 위험 탐색

## 화면 목적

**관심 분야와 키워드로 위험 후보를 좁히고, 시장성·손해 규모·보험 가능성을 비교하는 화면입니다.**

### 주요 기능 4가지

1. **분야·키워드로 위험 후보 탐색**
   - 전체, 개인 위험, 기업 위험, 법률 및 규제 위험, 사내 요청, 고객 요청으로 범위를 좁힙니다.
   - 검색어로 위험·기술·이슈 맥락을 찾습니다.
2. **후보별 시장성·손해 규모 비교**
   - 시장성, PML, 손해 측정 가능성 등 후보 간 차이를 비교합니다.
3. **AI 종합점수·위험 지표 확인**
   - 시장성, 손해 측정 가능성, 보험사고 성립성, 법적 책임·규제 부담, 통제 가능성, 손실 규모를 확인합니다.
4. **원문·상세 검토 연결**
   - 후보에 연결된 자료와 법령을 확인하고 `위험 상세` 화면으로 이동합니다.

### 정렬 기준

AI 종합점수 순, 시장성 순, 우연성 순, 법률 및 규제 리스크 순, PML 순, 후보명 순으로 정렬할 수 있습니다.

### 법률 및 규제 위험을 볼 때

일반 위험 후보처럼 점수표만 보는 것이 아니라, 왼쪽 법령 목록에서 법령을 선택하고 오른쪽에서 법령 기준 흐름, 연관 판례·손해 사례, 가입 의무 보험 약관 검토 조항, 공식 원문을 확인합니다.

### 용어

**PML(Probable Maximum Loss)**은 특정 위험 조건에서 발생할 수 있다고 추정하는 최대 손실 규모입니다. 화면의 `약 n억 원`은 정밀 보험료 산정값이 아니라 우선순위 비교용 추정치입니다.

### 캡처 권장

후보 목록과 선택 후보의 오른쪽 평가 카드가 한 화면에 보이는 화면

# 09. 위험 상세

## 화면 목적

**선택한 위험이 어디서 발생하고, 어떤 손해로 확산되며, 기존 보험으로 어디까지 연결되는지 깊이 확인하는 화면입니다.**

### 상단에서 먼저 보는 것

- 위험 제목과 핵심 요약
- 원문 중심 분석 여부
- 위험이 발생하는 구조
- 주요 손해 형태
- 책임 주체
- 현재 판단 상태
- 연결된 주요 원문 자료

### 위험 상세는 필터 화면이 아닙니다

상단의 가로 메뉴는 필터가 아니라 긴 내용을 빠르게 이동하기 위한 **섹션 목차**입니다. 항목을 누르면 해당 내용으로 이동합니다.

### 10개 섹션

1. 이슈 맥락
2. 보험 관점
3. 위험 구조
4. 정책·공식 자료
5. 손해 경로
6. 책임 주체
7. 기존 보험 연결
8. 상품화 질문
9. 위험 심층 해설
10. 근거 원장

### 사용법

처음에는 상단 요약과 `이 위험을 읽는 순서`를 읽고, 이후 필요한 섹션을 목차로 이동합니다. 결론보다 원문과 불확실성, 추가 확인 항목을 먼저 봅니다.

# 10. 위험 상세의 읽는 순서와 핵심 역할

## 오른쪽 안내 카드의 5단계

1. **어디서 위험이 발생하는가**: 기술·환경·행위·시장 변화의 출발점을 파악합니다.
2. **어떤 손해로 확산되는가**: 직접 손해, 방어비용, 영업중단, 제3자 피해를 구분합니다.
3. **누가 책임질 수 있는가**: 제조사, 운영자, 이용자, 플랫폼 등 책임 후보를 봅니다.
4. **기존 보험은 어디까지 가능한가**: 자동차·재산·배상책임·사이버 등 기존 보장과 비교합니다.
5. **무엇을 더 확인해야 하는가**: 원문, 사고 데이터, 약관, 계리·법무 검토 과제를 확인합니다.

### 핵심 판단 원칙

위험 신호가 있다고 해서 바로 보험사고가 되는 것은 아닙니다. 사고 시점, 손해 유형, 책임 주체, 보장 요건이 약관과 실제 자료로 확인되어야 합니다.

- 충족·불충족 상태

### 필터 기능

- 기준 그룹: 전체 기준 또는 특정 그룹

### 사용법

# 18. 약관 검토 탭

## 역할

새로운 담보를 만들 때 약관에 어떤 내용을 명확히 써야 하는지 검토합니다.

### 주요 검토 항목

- 보험 목적물과 가입 대상
- 보장하는 사고·손해의 정의
- 보험금 지급요건
- 사고 통지와 자료 제출
- 면책·고의·중대한 과실
- 자기부담금과 보상한도
- 기존 보험과의 중복·우선순위
- 손해사정과 분쟁 처리

### 질문으로 설명하기

“무엇이 발생하면 보험사고인가?”, “어떤 손해까지 지급하는가?”, “누가 어떤 자료를 제출해야 하는가?”, “보장하지 않는 상황은 무엇인가?”를 약관 문장으로 답할 수 있어야 합니다.

### 주의

이 탭은 약관 초안의 검토 포인트입니다. 법률 자문이나 최종 약관 승인을 대신하지 않습니다.

# 22. 개발자 테스트 모드 개요

## 화면 목적

**AI가 신호를 어떻게 분류하고 위험 후보·상세·리포트로 만드는지 단계별로 실험하는 공간입니다.**

### 개발자 워크플로

`01 신호 수집·분류` → `02 위험 후보 분석` → `03 위험 상세` → `04 종합 리포트`

### Mock과 실제 AI

- **MOCK**: 화면 흐름을 확인하기 위한 샘플 응답입니다. 실제 판단에 사용하지 않습니다.
- **GEMINI/실제 프록시**: 서버 전용 AI 연결을 통해 결과를 받는 모드입니다. 결과도 반드시 사람이 검토합니다.

### 핵심 원칙

개발자 모드의 목적은 AI 결과를 자동 승인하는 것이 아니라, 프롬프트·입력·응답·저장 결과를 검증하는 것입니다.

# 23. 개발자 모드의 AI 유틸리티 5개

| AI | 하는 일 | 결과 |
| --- | --- | --- |
| **신규위험 데이터 설계 AI** | 여러 문서를 읽고 위험 유형·엔터티·필드를 설계 | 화면용 데이터 구조 초안 |
| **신호 정리 AI** | 뉴스 수집 결과를 위험 신호로 분류·저장 | 관측 사실·신호·분류 결과 |
| **위험 후보화 AI** | 반복 신호를 위험 정의와 손실 시나리오로 구조화 | 위험 후보 초안 |
| **근거 검토 AI** | 출처의 최신성·독립성·반증 가능성을 점검 | 신뢰도·반증·근거 결과 |
| **리포트 초안 AI** | 검토 결과를 의사결정자가 읽는 초안으로 정리 | 종합 리포트 초안 |

### 비전공자 설명

AI 유틸리티는 각자 역할이 다른 작은 분석 도구입니다. 하나의 AI가 모든 판단을 한 번에 하는 구조가 아니라, 수집·정리·후보화·검증·보고 단계를 나누어 확인합니다.

# 24. 개발자 Step 1·2 사용법

## Step 1: 신호 수집·분류

- 뉴스 검색어와 데이터 입력 기준을 정합니다.
- 네이버 뉴스 검색 결과를 수집합니다.
- AI가 관측 사실, 위험 신호, 분류 결과를 구조화합니다.
- API 인증값은 저장소에 저장하지 않고 요청에만 사용합니다.

## Step 2: 위험 후보 분석

- 문서 또는 PDF 원문을 선택합니다.
- 위험 후보 기본 카드, 8개 스크리닝 지표, 법률·규제 카드, 사례·손실·시장 신호, 기사 분석 큐, 상품개발 후보 검토, 위험 신호 추세를 분석합니다.
- 현재 아티클 실행 또는 전체 아티클 자동 분석을 선택합니다.
- 결과를 서버 Excel에 저장하거나 Step 3 위험 상세로 넘깁니다.

### 주의

실제 문서가 아닌 Mock 결과는 저장·승인용으로 사용하지 않습니다.

# 25. 개발자 Step 3·4 사용법

## Step 3: 위험 상세 AI 분석

- 근거, 평가, 판단, 상품화, 담당자 인계 관련 분석을 실행합니다.
- 총 8개 분석 결과가 같은 articleId에 저장되어야 Step 4로 이동할 수 있습니다.
- PDF 원문과 Step 3 근거 원장을 비교합니다.
- 독립 출처 2개 충족 여부, 법령 검색 결과, 검증 상태, 상품화 검토 잠금 상태를 확인합니다.

## Step 4: 종합 리포트

- 같은 문서의 Step 3 결과가 모두 저장된 뒤 실행합니다.
- 실제 아티클 기반 리포트로 실무자 종합 리포트 UI를 확인합니다.
- 결과가 없는 섹션은 리포트에 표시하지 않습니다.

### 발표용 요약

“개발자 모드는 AI 결과를 바로 업무에 반영하는 곳이 아니라, 각 단계의 입력과 출력이 올바르게 연결되는지 테스트하는 검증 공간입니다.”

# 27. 영업부서 리포트 접수 흐름

## 3단계

1. **맥락을 남겨요**: 어떤 현장에서 어떤 질문·요청이 반복되었는지 요약합니다.
2. **사람이 검토해요**: 접수된 내용을 근거와 함께 담당자가 검토합니다.
3. **후속 경로를 정해요**: 기존 위험 후보 연결, 신규 후보 검토, 추가 자료 수집 등 다음 경로를 정합니다.

### 입력 검증

제목과 관찰 내용은 최소 글자 수를 충족해야 합니다. 고객 식별정보가 포함되지 않았는지 제출 전에 확인합니다.

### 현재 프로토타입 상태

운영 접수 API와 권한 큐가 연결되기 전의 내부 입력 화면입니다. 제출되었다고 해서 위험 후보가 자동 생성되거나 상품화가 승인되는 것은 아닙니다.

### 캡처 권장

입력 폼과 오른쪽 3단계 안내 카드가 함께 보이는 화면

- 생활 맥락: 주택·스마트홈, 자동차, 새 이동수단, 자녀 돌봄, 반려동물, 건강 관리, 여행·출장, 개인사업, AI·디지털 생활
- 걱정되는 상황
- 상담·확인 필요 수준

# 29. 개인 고객 입력과 결과 확인

## 입력 가이드

고객은 다음 세 가지를 중심으로 작성합니다.

1. **무엇을 사용하는지**: 제품, 기술, 이동수단, 주거환경
2. **어떤 사고가 걱정되는지**: 고장, 화재, 상해, 타인 피해
3. **무엇을 확인하고 싶은지**: 기존 보험의 보장과 빈틈

## 결과 화면

- **기존 상품 확인 후보**: 관련 상품, 관련성, 약관 확인 포인트, 공식 상품 링크
- **새롭게 살펴볼 생활 위험**: 확인할 빈틈, 연구 질문, 관련 키워드
- **공식 상품 페이지·상품공시 링크**: 실제 보장 확인을 위한 외부 공식 페이지

### 결과 해석

결과는 가입 권유나 보장 확정이 아닙니다. 실제 보장 범위와 가입 조건은 상품설명서·약관·특약·인수심사에서 확인합니다.

# 30. 개인정보와 고객 신호 처리 원칙

## 화면에 반드시 설명할 내용

- 이름·연락처·주민등록번호·상세 주소를 입력하지 않습니다.
- 자유입력에 개인정보 형식이 감지되면 저장 전 마스킹합니다.
- 고객 동의가 있을 때만 개인정보를 제거한 상황 키워드를 신규위험 연구 신호로 활용합니다.
- 단일 고객의 입력만으로 신규위험 후보를 자동 생성하지 않습니다.
- 고객 모드의 결과는 공식 상품 페이지와 약관 확인을 위한 탐색 결과입니다.

### 발표용 문구

“고객의 구체적인 신원을 수집하는 것이 아니라, 개인정보를 제거한 생활 맥락을 상품 연구의 참고 신호로 활용하는 구조입니다.”

# 31. 핵심 지표 용어집

| 용어 | 설명 | 읽는 방법 |

# 32. 근거·출처·기준일 읽기

## 출처 배지

`기관명 + 원문 →` 형태의 배지는 해당 내용의 출처 채널을 보여줍니다. 예: 보험연구원 원문, 보험개발원 원문, 금융감독원 원문, 법제처 원문.

## 기준일

자료가 어느 시점 기준인지 보여주는 정보입니다. 기준일이 오래되었거나 자료의 적용 범위가 불명확하면 최신 원문을 다시 확인해야 합니다.

## 원문과 해석의 구분

- 원문: 문서나 법령에서 직접 확인한 사실
- 해석: 보험 관점에서 연결한 의미
- 가정: 아직 자료로 확인되지 않은 전제
- 추가 확인: 다음 검토에서 확보해야 할 자료

### 발표용 원칙

“화면의 문장이 그럴듯해 보이는가”보다 “어떤 기관의 어떤 원문에서 나온 문장인가”를 먼저 확인합니다.

# 33. 처음 사용하는 사람을 위한 권장 시나리오

## 예시: 전기차 배터리 화재 위험

1. **위험 레이더**에서 최근 30일 TOP 5 후보를 확인합니다.
2. **위험 탐색**에서 기업 위험 또는 관련 키워드로 후보를 비교합니다.
3. 선택 후보의 시장성, PML, AI 종합점수를 확인합니다.
4. **위험 상세**에서 위험 구조 → 손해 경로 → 책임 주체 → 기존 보험 연결 순으로 읽습니다.
5. 위험 심층 해설의 기관명 원문 배지를 눌러 실제 자료를 확인합니다.
6. **종합 리포트**의 보장 공백과 약관 검토 탭에서 상품화 질문을 정리합니다.
7. 불충족 기준과 추가 확인사항을 담당 부서에 전달합니다.

### 이 시나리오의 결론

“전기차 배터리 화재가 보험상품이 된다”가 아니라, 어떤 손해를 어떤 조건에서 보장할지 검토할 자료와 질문이 정리되었다는 의미입니다.

# 34. 운영 시 반드시 지킬 원칙

- AI 결과를 사실로 확정하지 말고 원문을 확인합니다.
- 시장성·PML·종합점수는 우선순위 참고값으로 사용합니다.
- 상품명·보장범위·보험료·가입 가능 여부를 최종 결론처럼 표현하지 않습니다.
- 법률·규제 위험은 법령 원문과 최신 적용 기준을 확인합니다.
- 고객·영업 입력에는 개인정보를 넣지 않습니다.
- 샘플 데이터와 실제 문서 기반 결과를 구분합니다.
- 근거 ID, 기준일, 불확실성, 반증 또는 보류 이유를 남깁니다.
- 최종 상품화는 상품·법무·계리·보상·영업 등 담당 검토 후 결정합니다.

**위험을 발견하는 것에서 끝나지 않고, 근거를 확인하고 다음 판단으로 연결합니다.**
