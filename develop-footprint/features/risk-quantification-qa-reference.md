## 1. Q&A에서 먼저 말할 기본 답변

### 30초 답변

“현재 화면의 점수와 금액은 실제 보험료나 보험금 확정값이 아닙니다. 공개 원문과 시나리오를 이용해 위험 후보의 우선순위를 비교하기 위한 프로토타입입니다. 이상적인 운영 단계에서는 노출량, 사고 빈도, 손해 심도, 누적위험, 기존 보험금 지급자료를 기반으로 계리모형을 구축하고, 법무·상품·보상·재보험 검토를 거쳐 최종 산출합니다.”

### 가장 짧은 답변

“현재 산식은 상품 확정 산식이 아니라 신규위험을 어떤 순서로 검토할지 정하는 탐색용 산식입니다.”

### 발표에서 반드시 구분할 세 가지

1. **이론적 산식**: 실제 보험상품 운영에 적합한 계리·위험관리 모델
2. **현재 데모 산식**: 화면 흐름을 보여주기 위한 공개자료·시나리오 기반 프로토타입
3. **최종 판단**: 상품·법무·계리·보상·재보험 담당자가 근거를 확인한 뒤 내리는 결정

## 2. 프로젝트가 가정하는 업무 흐름

```text
신호 발견
  → 위험 정의
  → 노출량 산정
  → 사고 빈도·손해 심도 추정
  → PML·누적위험 분석
  → 기존 보험과 보장 공백 비교
  → 보험성 요건 검토
  → 시장성·수요 검토
  → 보험료·한도·재보험 산출
  → 사람의 상품화 판단
```

이 서비스는 산업·기술·법률·시장 변화에서 발생하는 새로운 위험을 발견하고, 보험의 관점에서 검토할 질문과 근거를 정리하는 워크벤치다.

위험 후보는 곧바로 상품이 되지 않는다. 후보화 이후에는 손실사건, 노출집단, 책임 주체, 기존 보장, 보장 공백, 데이터 충분도, 법률·약관 조건을 차례로 확인해야 한다.

참고: [신규위험 탐색 실무자 기준](../roles/emerging-risk-analyst.md)

## 3. 이상적인 신규위험 평가 구조

실제 운영에서는 여러 판단을 하나의 점수로 바로 합치지 않는다.

### 3.1 위험 정의

먼저 아래 네 가지를 고정한다.

- 무엇이 변했는가?
- 어떤 사건이 발생하는가?
- 누가 경제적 손해를 입는가?
- 기존 보험으로 어디까지 보장되는가?

### 3.2 손해 구조

손해는 가능한 한 다음과 같이 분리한다.

```text
직접 재산손해
+ 신체손해
+ 제3자 배상책임
+ 방어·조사·법률비용
+ 복구·긴급대응 비용
+ 영업중단·추가비용
- 회수금·잔존물
- 기존 보험 지급액
```

모든 손해가 보험으로 보장되는 것은 아니다. 약관상 보장 대상, 면책, 손해의 인과관계와 지급 한도를 별도로 확인해야 한다.

### 3.3 보험성 판단

보험성 판단은 수요보다 먼저 확인해야 하는 게이트다.

- 피보험이익이 존재하는가?
- 사고가 우연하고 비고의적인가?
- 실제 경제적 손해를 보전하는 구조인가?
- 고의·사행성·투자수익 보장 구조가 아닌가?
- 사고와 손해를 약관으로 명확하게 정의할 수 있는가?

이 필수 조건 중 하나가 명확히 충족되지 않으면 시장성이 높아도 상품화 결론을 내릴 수 없다.

## 4. 이상적인 시장성·TAM·SAM·SOM 산식

### 4.1 TAM

TAM은 전체 도달 가능 시장이다.

```text
TAM
= 가입 가능한 전체 대상 수
× 대상별 예상 연간 보험료
```

예를 들어 전기차 충전시설 17,189곳을 대상으로 하고 시설당 연간 보험료를 70만 원으로 가정하면:

```text
17,189곳 × 700,000원
= 12,032,300,000원
≈ 약 120억 원/년
```

### 4.2 SAM

실제 판매할 수 있는 범위를 반영한다.

```text
SAM
= TAM
× 판매 가능 지역 비율
× 보장 대상 적합 비율
× 인수 가능 비율
```

### 4.3 SOM

초기 실제 확보 가능한 시장을 뜻한다.

```text
SOM
= SAM
× 예상 가입 전환율
× 판매채널 도달률
```

### 4.4 Q&A 설명

“TAM은 실제 매출 예측이 아니라 전체 잠재 시장의 상한입니다. 실제 사업계획에서는 판매 가능 대상만 남긴 SAM과 예상 전환율을 적용한 SOM을 별도로 계산해야 합니다.”

현재 데모의 `TAM 약 65억~191억 원/년`은 시장 범위를 보여주는 시나리오 값이다. `시장성 A·84점`은 TAM 금액이 아니라 수요·보장 공백·데이터·상품화 가능성을 점수화한 별도 지표다.

## 5. 이상적인 사고 빈도·손해 심도 산식

보험료 산정의 기본은 빈도와 심도다.

```text
예상 연간 손해액
= 노출량
× 사고 빈도
× 사고당 평균 손해액
```

노출군별 위험이 다르면 다음과 같이 계산한다.

```text
Expected Loss
= Σ(노출군별 노출량
   × 노출군별 사고 빈도
   × 노출군별 평균 손해액)
```

실제 운영에서 필요한 자료는 다음과 같다.

- 계약 건수와 계약기간
- 시설·차량·기기 노출량
- 사고 건수와 사고 발생률
- 평균 손해액과 손해액 분포
- 사고 원인별 손해액
- 기존 보험 지급액
- 사고 미보고·지연보고 건수
- 지역·시설 규모·업종별 차이

### 5.1 통계모형 관점

사고 빈도는 포아송 또는 음이항 모형으로, 손해 심도는 감마·로그정규 등으로 모델링할 수 있다.

```text
사고 빈도 λ
= 보정된 사고 건수 ÷ 보정된 노출량
```

```text
기대손해액
= 노출량 × E[빈도] × E[손해 심도]
```

신규위험은 데이터가 짧거나 사고가 적을 수 있으므로 유사위험·해외자료·전문가 판단을 활용하되, 신뢰도와 보정 여부를 별도 기록해야 한다.

## 6. 이상적인 PML 산식

PML은 평균 손해액이 아니라 큰 손실 시나리오를 판단하는 지표다.

연간 총손해액을 다음과 같이 정의한다.

```text
L
= 사고 1 손해액
+ 사고 2 손해액
+ ...
+ 사고 n 손해액
```

확률분포를 구축하면:

```text
PML99.5
= 연간 총손해액 분포의 99.5% 분위수
```

극단손해의 평균까지 반영하면:

```text
TVaR99.5
= PML99.5 초과 손해의 평균
```

### 6.1 누적위험

동일한 원인으로 여러 계약에 손해가 발생하면 누적위험이 된다.

```text
누적손해
= 개별 사고 손해
+ 동일 시설 동시 피해
+ 동일 지역 동시 피해
+ 동일 기술·공급망 동시 피해
+ 상관관계가 높은 계약군 손해
```

전기차, 데이터센터, 사이버, 자연재해 위험에서는 단일 사고 손해뿐 아니라 같은 시설·지역·기술에 연결된 계약을 함께 계산해야 한다.

### 6.2 Q&A 설명

“PML은 보험금 지급액이 아니라, 특정 사고나 누적 사고에서 발생할 수 있는 최대 손실을 추정한 값입니다. 실제 보험금은 약관상 보장범위, 자기부담금, 보상한도, 기존 보험 지급액을 반영해 결정됩니다.”

## 7. 현재 데모의 PML 예시: 전기차 지하주차장 화재

현재 데모는 통계분포를 시뮬레이션하지 않고 최대 동시 피해 시나리오를 사용한다.

### 7.1 보수적 시나리오

```text
전소 차량 87대 × 3,000만 원
= 26억 1,000만 원

부분 피해 차량 783대 × 50만 원
= 3억 9,150만 원

시설·긴급대응 비용
= 5억 원

합계
= 35억 150만 원
≈ 약 35억 원
```

### 7.2 기준 시나리오

```text
전소 차량 87대 × 4,000만 원
= 34억 8,000만 원

부분 피해 차량 783대 × 100만 원
= 7억 8,300만 원

시설·긴급대응 비용
= 10억 원

합계
= 52억 6,300만 원
≈ 약 53억 원
```

### 7.3 확대 시나리오

```text
전소 차량 87대 × 5,000만 원
= 43억 5,000만 원

부분 피해 차량 783대 × 200만 원
= 15억 6,600만 원

시설·긴급대응 비용
= 20억 원

합계
= 79억 1,600만 원
≈ 약 79억 원
```

따라서 화면에는 다음과 같이 표시된다.

```text
PML 범위: 약 35억~79억 원
기준 PML: 약 53억 원
```

### 7.4 반드시 붙일 설명

“약 53억 원은 실제 사고 통계를 기반으로 확정한 금액이 아니라, 전소 차량 수·부분 피해 차량 수·차량가액·시설 복구비를 조합한 기준 시나리오입니다.”

## 8. 이상적인 보험료 산식

이론적으로 보험료는 다음 구조다.

```text
보험료
= 예상 보험금
+ 사업비
+ 재보험료
+ 자본비용·위험마진
+ 이익마진
```

손해율 기반으로 표현하면:

```text
보험료
= (예상 연간 손해액
   + 재보험료
   + 고정비
   + 자본비용)
  ÷ (1 - 변동사업비율 - 목표이익률)
```

실제 산정에서는 보상한도, 자기부담금, 면책, 재보험, 손해액 분포, 계약자별 위험등급을 함께 반영해야 한다.

## 9. 현재 데모의 보험료 산식

현재 상품개발 제안 화면은 명시적인 시나리오 산식을 사용한다.

```text
일반 예상손해액
= PML × 연간 사고확률 × 평균 손해심도 비율
```

```text
꼬리위험 금액
= PML × 꼬리위험 가산율
```

```text
예상 연간 손해액
= 일반 예상손해액 + 꼬리위험 금액
```

```text
제안 보험료
= 예상 연간 손해액 ÷ 목표 손해율
 + 재보험 비용
 + 예상 연간 손해액 × (사업비율 + 불확실성 가산율)
```

참고: [상품개발 제안 프로토타입 산식](../../src/report/data/product-proposal-mock.ts:368)

## 10. 현재 데모 기준 시나리오 계산

| 항목 | 값 |
| --- | ---: |
| 기준 PML | 53억 원 |
| 연간 사고확률 | 0.1% |
| 평균 손해심도 | PML의 1.2% |
| 꼬리위험 가산율 | 0.00025% |
| 목표 손해율 | 60% |
| 사업비율 | 15% |
| 불확실성 가산율 | 8% |
| 재보험 비용률 | 0.0002% |

### 10.1 일반 예상손해액

```text
53억 원 × 0.001 × 0.012
= 63,600원
```

### 10.2 꼬리위험 금액

```text
53억 원 × 0.0000025
= 13,250원
```

### 10.3 예상 연간 손해액

```text
63,600원 + 13,250원
= 76,850원
```

### 10.4 재보험 비용

```text
53억 원 × 0.000002
= 10,600원
```

### 10.5 제안 보험료

```text
76,850 ÷ 0.60
+ 10,600
+ 76,850 × (0.15 + 0.08)
= 약 156,359원
```

화면에서는 천 원 단위로 반올림해:

```text
계약당 연보험료 약 156,000원
```

### 10.6 예상 손해율

코드는 반올림된 보험료를 사용한다.

```text
76,850 ÷ 156,000
= 약 49.3%
```

### 10.7 보상한도

```text
53억 원 × 75%
= 39억 7,500만 원
```

### 10.8 누적 보상한도

```text
39억 7,500만 원 × 1.5
= 59억 6,250만 원
```

### 10.9 자기부담금

```text
76,850원 × 35%
≈ 27,000원
```

### 10.10 재보험 판단

```text
기준 PML 53억 원
> 회사 보유한도 30억 원
```

따라서 데모에서는 재보험을 `권고`로 표시한다.

### 10.11 데모 산식의 한계

현재 값은 실제 요율이 아니다. 사고확률, 평균 손해심도, 꼬리위험 가산율, 사업비율, 불확실성 가산율 모두 시나리오 입력값이다.

“사고확률과 손해심도, PML을 가정했을 때 보험료·보상한도·재보험 판단이 어떤 방향으로 연결되는지를 보여주는 예시”라고 설명한다.

## 11. 위험 탐색 점수 산식

### 11.1 일반 후보의 8개 지표 평균

현재 일반 위험 후보는 8개 지표를 각각 1~5점으로 평가한 뒤 단순 평균한다.

```text
선별점수
= (시장 수요
 + 우연성
 + 누적위험
 + 손해 측정 가능성
 + 역선택
 + 도덕적 해이
 + 데이터 신뢰도
 + 법률·규제 노출)
÷ 8
```

이 값은 `0~5점` 척도의 후보 선별점수다.

참고: [위험 탐색 선별점수](../../src/domain/risk/riskExplorationDemo.ts:361)

### 11.2 전기차 위험 현재 입력 예시

```text
시장 수요          4.6
우연성              4.0
누적위험            5.0
측정 가능성         4.0
역선택              5.0
도덕적 해이         3.0
데이터 신뢰도       4.25
법률 노출           5.0
```

```text
(4.6 + 4.0 + 5.0 + 4.0 + 5.0 + 3.0 + 4.25 + 5.0)
÷ 8
= 4.35625
≈ 4.4 / 5점
```

이 점수는 보험상품 적합도나 보험료가 아니라 상세 검토 우선순위다.

### 11.3 각 지표의 의미

| 지표 | 의미 |
| --- | --- |
| 시장 수요 | 실제 가입 대상과 보험 수요가 있는가 |
| 우연성 | 사고가 비고의적이고 사전에 확정되지 않는가 |
| 누적위험 | 하나의 원인으로 여러 계약이 동시에 손해를 입는가 |
| 측정 가능성 | 사고 빈도와 손해액을 객관적으로 계산할 수 있는가 |
| 역선택 | 고위험 가입자의 집중을 인수 단계에서 통제할 수 있는가 |
| 도덕적 해이 | 가입 후 고의·과장청구·관리소홀을 통제할 수 있는가 |
| 데이터 신뢰도 | 자료의 양·최신성·대표성·출처가 충분한가 |
| 법률 노출 | 책임 주체와 법률·약관상 보장범위가 명확한가 |

## 12. 현재 상품화 종합점수 산식

문서 기반 후보는 별도의 상품화 종합점수 산식을 사용한다.

```text
시장성
= 수요 45%
 + 도덕적 해이 15%
 + 역선택 20%
 + 데이터 신뢰도 20%
```

```text
PML 지표
= 우연성 45%
 + 누적위험 35%
 + 역선택 20%
```

```text
통제 가능성
= 100 - PML 지표 × 55%
```

```text
법률 준비도
= 100 - 법률 노출 × 20
```

```text
근거 충분도
= 데이터 신뢰도 × 20
```

```text
상품화 종합점수
= 시장성 35%
 + PML 지표 20%
 + 통제 가능성 15%
 + 법률 준비도 15%
 + 근거 충분도 15%
```

참고: [상품화 종합점수 실제 코드](../../src/features/risk-catalog/productizationScore.ts:7)

### 12.1 해석 시 주의

이 점수는 상품화 적합도만 나타내는 점수가 아니다.

- PML이 높으면 손실 규모가 크므로 우선 검토 필요성이 올라갈 수 있다.
- 법률 준비도와 통제 가능성이 낮으면 실제 상품화에는 제약이 생긴다.
- 따라서 종합점수가 높아도 상품 출시를 의미하지 않는다.

### 12.2 전기차 원점수를 같은 산식에 넣었을 때

현재 전기차 8개 원점수를 문서 기반 상품화 산식에 넣으면 다음과 같이 계산된다.

```text
시장성
= (4.6×0.45 + 3.0×0.15 + 5.0×0.20 + 4.25×0.20) × 20
= 87.4점
```

```text
PML 지표
= (4.0×0.45 + 5.0×0.35 + 5.0×0.20) × 20
= 91점
```

```text
통제 가능성
= 100 - 91×0.55
= 49.95점
```

```text
법률 준비도
= 100 - 5.0×20
= 0점
```

```text
근거 충분도
= 4.25×20
= 85점
```

```text
종합점수
= 87.4×0.35
 + 91×0.20
 + 49.95×0.15
 + 0×0.15
 + 85×0.15
≈ 69.0점
≈ 3.5 / 5점
```

다만 이 계산은 현재 전기차 일반 후보의 원점수에 문서 기반 산식을 적용한 참고 계산이다. 현재 일반 `/risks` 경로에서는 8개 평균 `4.4/5`가 대표 선별점수로 사용되고, 리포트의 `시장성 A·84점`과 PML 시나리오는 별도 프로토타입 데이터 경로를 사용한다.

## 13. 84점과 4.4점이 다른 이유

Q&A에서 가장 자주 질문될 수 있는 부분이다.

### 답변

“84점은 시장성 기준을 100점으로 환산한 값이고, 4.4점은 8개 위험 평가 지표의 평균을 5점 기준으로 표시한 값입니다. 서로 다른 지표와 산식이기 때문에 단순히 4.4에 20을 곱해 88점으로 바꾸는 관계가 아닙니다.”

현재 데모에는 다음 데이터 경로가 함께 존재한다.

- 일반 위험 후보: 8개 지표 평균 `0~5점`
- 문서 기반 후보: 시장성·PML·통제 가능성·법률 준비도·근거 충분도
- 전기차 기준 리포트: 시장성 `A·84점`, PML `35억~79억 원`
- 대시보드 일부: 발표용 큐레이션 샘플 배열

### 이상적인 운영 개선 방향

운영 단계에서는 모든 점수에 다음 메타데이터를 연결해야 한다.

```text
formulaVersion
scale
meaning
sourceAsOf
generatedAt
dataStatus
confidence
isMockData
```

즉 같은 후보라도 화면마다 숫자만 보여주는 것이 아니라, 그 숫자의 의미와 산식을 함께 보여줘야 한다.

참고: [탭 2 점수 계약](../features/tab-2-risk-candidate-development.md:24), [탭 3 점수 의미 분리](../features/tab-3-risk-detail-development.md:22)

## 14. 이상적인 상품화 판단 방식: 게이트 + 우선순위

실제 운영에서는 모든 요소를 평균 내면 안 된다.

### 14.1 보험성 필수 게이트

```text
보험성 게이트
= 피보험이익
× 우연성
× 실손보상 가능성
```

각 항목을 충족하면 1, 불충족하면 0으로 표시한다.

```text
보험성 게이트 = 1
→ 다음 상품화 검토 진행 가능
```

```text
보험성 게이트 = 0
→ 상품화 중단 또는 구조 재설계
```

### 14.2 상품화 우선순위

보험성 게이트를 통과한 후보끼리 비교한다.

```text
우선순위
= 시장성
 + 보장 공백
 + 손해 측정 가능성
 + 통제 가능성
 + 위험 분산 가능성
 + 데이터 준비도
 - 법률 불확실성
 - 누적위험 부담
```

### 14.3 불확실성 보정

```text
보정 우선순위
= 기본 우선순위
× 근거 신뢰도
× 데이터 완성도
```

이 구조의 장점은 시장성이 높더라도 법률적으로 보장할 수 없는 위험이 단순 평균 때문에 높은 점수를 받는 문제를 막는 것이다.

## 17. Q&A 예상 질문과 답변

### Q1. 이 점수가 실제 보험료 산출에 쓰이나요?

“아닙니다. 현재는 후보 우선순위와 추가 검토 필요성을 보여주는 예비 지표입니다. 실제 보험료는 사고 빈도, 손해 심도, 손해율, 사업비, 재보험, 자본비용을 반영해 계리적으로 산출해야 합니다.”

### Q2. PML이 보험금 지급액인가요?

“아닙니다. PML은 특정 사고 또는 누적 사고에서 발생할 수 있는 최대 손실 추정치입니다. 실제 보험금은 약관상 보장범위, 자기부담금, 보상한도, 기존 보험 지급액을 반영해 결정됩니다.”

### Q3. 시장성 84점은 무엇을 의미하나요?

“시장 수요, 잠재 가입 대상, 데이터 신뢰도, 상품화 가능성을 종합한 탐색용 점수입니다. 84%의 가입 확률이나 84억 원의 시장 규모를 뜻하지 않습니다.”

### Q4. PML이 높으면 상품성이 높은 건가요?

“손실 규모가 크기 때문에 검토 우선순위는 높아질 수 있지만, 상품성이 높다는 뜻은 아닙니다. 통제 가능성, 법률 준비도, 재보험 가능성, 데이터 확보 수준을 함께 봐야 합니다.”

### Q5. 왜 약 53억 원으로 계산했나요?

“전소 차량, 부분 피해 차량, 시설·긴급대응 비용을 기준 시나리오로 합산한 결과입니다. 실제 사고 통계가 아닌 공개자료 기반 시나리오 추정치입니다.”

### Q6. 실제 상품으로 만들 수 있나요?

“현재는 상품화 가능성을 검토할 수 있는 후보입니다. 실제 상품화 여부는 피보험이익, 우연성, 보장 공백, 손해 측정 가능성, 약관 명확성, 요율자료, 재보험 조건을 확인한 뒤 결정합니다.”

### Q7. AI가 상품화 가능 여부를 결정하나요?

“아닙니다. AI는 원문을 구조화하고 검토 질문과 판단 근거를 정리합니다. 최종 상품화 판단은 상품·법무·계리·보상·재보험 담당자의 검토가 필요합니다.”

### Q8. 현재 수치는 실제 데이터인가요?

“일부는 공개 원문을 바탕으로 한 예시이고, 일부는 화면 흐름을 보여주기 위한 SAMPLE 시나리오입니다. 실제 내부 계약·보험금·보험료 데이터와 연결되기 전까지는 운영 판단에 사용할 수 없습니다.”

### Q9. 왜 화면마다 점수가 달라 보이나요?

“현재 데모에는 후보 선별점수, 시장성 점수, 문서 기반 상품화점수, 대시보드 큐레이션 값이 목적별로 분리되어 있습니다. 운영 단계에서는 점수 의미와 산식 버전을 하나의 공통 계약으로 통합해야 합니다.”

### Q10. 데이터가 부족하면 어떻게 하나요?

“0점으로 임의 처리하지 않고 `확인 필요`, `추가 자료 필요`, `검토 보류` 상태로 남겨야 합니다. 부족한 데이터 자체를 다음 검토 과제로 기록합니다.”

## 19. 최종 발표용 문장

### 기본형

“이 프로젝트의 산식은 정식 보험료 산출모형이라기보다, 신규위험을 어떤 순서로 검토할지 정하는 탐색용 계량 프레임입니다.”

### 이론 강조형

“이상적인 운영 단계에서는 노출량·사고 빈도·손해 심도·누적위험을 기반으로 기대손해액과 PML을 산출하고, 보험성 게이트와 법률·약관 검토를 통과한 후보에 대해서만 보험료·보상한도·재보험 구조를 계리적으로 검증합니다.”

### 데모 강조형

“현재 화면은 실제 상품을 확정하기 위한 것이 아니라, 공개 근거와 시나리오 수치를 이용해 어떤 위험을 먼저 검토하고 어떤 자료를 더 모아야 하는지 보여주는 프로토타입입니다.”

### 가장 안전한 종합 답변

“화면의 점수와 금액은 결론이 아니라 다음 판단을 위한 출발점입니다. 숫자 자체보다 어떤 원문과 가정에서 나왔는지, 어떤 불확실성이 남아 있는지, 다음에 어떤 내부자료를 확인해야 하는지를 함께 보는 것이 이 워크벤치의 핵심입니다.”
