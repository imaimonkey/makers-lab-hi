# 1~4 실무자 워크플로 계약

현재 1~4 화면은 통합을 위한 프레임과 샘플이다. 아래 계약을 유지하면 각 팀이 다른 데이터 소스와 UI를 구현해도 원래 버전에 연결할 수 있다.

## 공통 판단 모델

모든 단계는 다음 네 축을 별도로 보존한다.

| 축 | 답해야 하는 질문 | 예시 근거 |
| --- | --- | --- |
| 신호 강도 | 변화가 실제로 커지고 있는가? | 빈도·검색량·사고·투자·규제 변화 |
| 근거 신뢰도 | 독립적이고 최신인 출처가 충분한가? | 원문, 데이터 계보, 수집 시각, 반증 |
| 손실 명확성 | 누구에게 어떤 경제적 손실이 생기는가? | 손실사건, 노출집단, 빈도·심도 가설 |
| 상품화 적합성 | 보험으로 이전 가능하고 운영 가능한가? | 기존 보장 공백, 데이터, 인수·청구 가능성 |

축을 하나의 종합 점수로만 제공하지 않는다. 가중 합계가 필요하면 원 점수와 가중치, 계산 버전을 함께 남긴다.

## 1. 신규위험 통합 대시보드

### 사용자 질문

- 최근 관측에서 무엇이 유의미하게 변했는가?
- 어떤 후보가 오늘 검토 또는 재검토가 필요한가?
- 어떤 수집 채널의 데이터가 오래됐거나 실패했는가?
- 고객 채널에서 반복되는 미충족 위험은 무엇인가?

### 필수 입력

- `SignalSummary[]`: 채널, 주제, 관측값, 기준값, 변화율, 출처, 관측·수집 시각
- `SourceHealth[]`: 소스, 마지막 성공, 지연, 실패, 데이터 품질
- `RiskCandidateSummary[]`: 공통 후보 필드와 현재 상태
- `CustomerSignalAggregate[]`: 최소 집계 기준을 통과한 비식별 범주

### 필수 출력

- 필터와 정렬이 포함된 후보 탐색 쿼리
- 후보 상세 경로 `/risks/:riskId`
- 검토 큐에 후보 생성 요청. 자동 확정이 아닌 초안 상태여야 한다.

### 완료 조건

- 데이터 최신 시각, 실패 채널, 샘플/실제 데이터 여부가 보인다.
- 변화량과 절대량을 혼동하지 않는다.
- 같은 사건의 재게시를 독립 근거로 중복 계산하지 않는다.
- 로딩, 빈 상태, 부분 실패를 전체 실패와 구분한다.

## 2. 위험 후보 목록

### 사용자 질문

- 어떤 후보를 지금 상세 평가해야 하는가?
- 동일 위험의 중복 후보나 오래된 후보가 있는가?
- 담당·상태·다음 검토일이 비어 있는 후보는 무엇인가?

### 후보 최소 필드

```text
id, title, theme, riskStatement, lossEvent, exposedParty,
cause, lossType, signalStrength, evidenceConfidence,
productFit, evidenceCount, status, owner, updatedAt, nextReviewAt
```

### 필수 상호작용

- 주제, 상태, 담당자, 근거 신뢰도, 상품화 적합성 필터
- 검색, 정렬, 저장된 보기, 상세 진입
- 중복 후보 병합 제안과 병합 전 영향 확인
- 여러 후보의 상태 일괄 변경은 권한과 감사 로그가 있을 때만 허용

### 금지

- 기사 제목만 나열한 목록
- 근거 없는 자동 우선순위 확정
- 상태·담당자 변경 이력 덮어쓰기

## 3. 위험 상세·상품화 평가

### 화면 구조

1. 한 문장 위험 정의: `변화 원인 → 노출집단 → 손실사건`
2. 신호 추세와 데이터 품질
3. 근거 원장: 출처 원문, 발행·수집 시각, 발췌, 주장, 중복군, 신뢰도
4. 반증·대안 설명
5. 기존 상품·특약·약관과의 비교
6. 상품화 평가: 보험가능성, 데이터, 가격, 인수, 청구, 법무·규제, 소비자 가치
7. 의견·질문·결정 이력

### 필수 출력

- `PROGRESS`, `HOLD`, `DROP` 결정과 이유
- 결정에 사용한 근거 ID와 반증 ID
- 기존 보장 확인 결과와 미확인 항목
- 상품 가설 초안: 대상, 보험사고, 보장, 주요 면책 후보
- 다음 조사 과제, 담당자, 기한

### 평가 원칙

- `기존 상품에서 검색되지 않음`은 `보장되지 않음`의 증거가 아니다.
- AI 요약은 원문 출처와 문장 수준 근거를 열 수 있어야 한다.
- 모델 확률이나 점수는 결정자가 이해할 수 있는 버전·입력·한계를 함께 제시한다.
- 의견은 수정 덮어쓰기보다 작성자·시각·버전이 남는 방식으로 저장한다.

## 4. 종합 리포트

### 목적

관리자, 상품, 계리, 보상, 법무·준법, 채널 담당자가 같은 근거를 보고 다음 투자 여부를 결정할 수 있는 문서를 만든다.

### 필수 섹션

- 요약 및 요청 결정
- 위험 정의와 변화 동인
- 노출집단·손실 시나리오
- 근거·반증·불확실성
- 기존 상품/약관 비교와 공백 가설
- 상품 가설과 고객 가치
- 데이터·가격·인수·청구 가능성
- 법무·규제·소비자보호 검토 필요 사항
- 결정, 소유자, 기한, 다음 게이트

### 완료 조건

- 보고서 수치와 문장이 근거 ID로 역추적된다.
- 생성 시점의 스냅샷과 이후 변경 이력을 구분한다.
- 진행/보류/종료가 분명하고 미결 질문이 담당자·기한과 연결된다.
- PDF나 문서 내보내기 전 접근권한과 개인정보 검사를 거친다.

## 단계 간 상태 예시

```text
DRAFT → TRIAGE → ASSESSING → REVIEW_READY
                     ↘ HOLD → 재검토
                     ↘ DROP
REVIEW_READY → PRODUCT_DISCOVERY
```

상태명은 백엔드와 합의 후 확정하되, `신호`, `후보`, `상품 개발 과제`는 서로 다른 엔터티로 유지한다.
