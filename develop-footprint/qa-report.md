# 시스템 QA 리포트

검증일: 2026-07-18  
대상: 실무자 1~4 프레임, 개인고객 상황 탐색, 사용자 전환, 비식별 신호 환류

## 수정한 결함

| 결함 | 원인 | 조치 |
| --- | --- | --- |
| 위험 상세에서 `위험 후보`와 `평가 워크벤치`가 동시 활성 | `/risks` 접두어 매칭과 React Router 기본 부분 매칭이 겹침 | 목록은 정확 경로, 상세는 `/risks/:id` 전용 규칙으로 분리하고 `aria-current`도 하나만 부여 |
| 위험 후보별 상세 본문 불일치 | 제목·점수만 후보 데이터였고 위험 문장·평가는 AI 고정값 | 네 개 샘플 후보별 위험 문장, 노출, 손실, 평가, 결정, 근거 샘플 분리 |
| 고객 초기 화면의 큰 빈 결과 카드 | 결과 전에도 입력과 결과가 비슷한 비중을 차지함 | 초기에는 입력 1.3 : 작성 가이드 0.7, 분석 후에는 입력 0.78 : 결과 1.22로 전환 |
| 미구현 버튼이 동작 가능한 것처럼 보임 | 프레임용 버튼에 상태 표시가 없음 | 근거 추가·새 리포트·리포트 열기를 비활성화하고 `미연동`·설명 표시, 불필요한 알림 버튼 제거 |
| 파비콘 요청 404 | 아이콘 파일 없음 | 코드 기반 `public/favicon.svg` 추가 |
| 존재하지 않는 위험 ID의 AI 상세 fallback | 첫 번째 후보로 묵시적 대체 | 요청 ID를 표시하고 위험 후보 목록으로 복귀하는 상세 전용 오류 상태 추가 |

## 경로 QA

| 경로 | 데스크톱 | 768px | 390px | 활성 메뉴 |
| --- | --- | --- | --- | --- |
| `/` | 통과 | 통과 | 통과 | 위험 레이더 1개 |
| `/risks` | 통과 | 통과 | 통과 | 위험 후보 1개 |
| `/risks/:riskId` | 통과 | 통과 | 통과 | 평가 워크벤치 1개 |
| `/reports` | 통과 | 통과 | 통과 | 종합 리포트 1개 |
| `/customer-insight` | 통과 | 통과 | 통과 | 고객 셸, 실무자 메뉴 없음 |
| 알 수 없는 일반 경로 | 통과 | 해당 없음 | 통과 | 활성 메뉴 없음, 404 표시 |

1440px, 768px, 390px에서 문서 `scrollWidth`가 viewport 너비를 넘지 않는 것을 확인했다. 목록·리포트의 넓은 표는 페이지 전체가 아니라 지정된 내부 영역에서만 스크롤한다.

## 상호작용 QA

- 위험 후보 검색 결과 0건과 빈 상태 표시
- `신규` 상태 필터 결과 1건 및 `aria-pressed` 상태
- ESS 후보 선택 → `/risks/home-ess-fire` → ESS 위험 문장 표시
- 빈 고객 상황 제출 → 12자 이상 안내 오류
- 데모 예시 → 상품 후보 3개, 신규 생활 위험 2개
- 연구 동의 없음 → 분석 결과 동일, 연구 의견 전송만 비활성
- 연구 동의 있음 → 비식별 신호 1건 저장 및 대시보드 반영
- 이메일·전화번호 포함 입력 → `[이메일 삭제]`, `[연락처 삭제]`로 저장
- `데모 큐 비우기` → 대시보드·로컬 저장소 0건
- 실무자 ↔ 개인고객 전환 후 각 전용 셸만 표시

## 구조·접근성 검사

- 주요 페이지의 중복 `id` 없음
- 빈 `href` 없음
- 레이블 없는 input, select, textarea, 빈 아이콘 버튼 없음
- 상세 경로의 활성 항목과 `aria-current="page"`가 하나뿐임
- 브라우저 런타임 예외와 콘솔 오류 없음
- `npm run check`, `git diff --check`, Markdown 내부 링크 검사 통과

## 잔여 위험

- 1~4는 운영 API가 없는 샘플 프레임이므로 쓰기 기능은 의도적으로 비활성 상태다.
- 고객 추천은 규칙 기반 콘셉트이며 실제 상품 마스터·최신 약관·인수 심사와 연결되지 않았다.
- 현재 브라우저 QA는 로컬 Chromium CDP 기반이다. 기능 팀이 1~4를 구현할 때 Playwright 등 CI 회귀 테스트로 이 체크리스트를 이전해야 한다.
- 외부 공식 상품 페이지의 판매 상태와 링크 유효성은 운영 상품 마스터에서 주기적으로 재검증해야 한다.
