# 5. 고객 인사이트 루프

## 현재 구현

`/customer-insight`는 실무자 셸과 분리된 공개 웹 형태다. 고객이 상황을 입력하면 규칙 기반 엔진이 최대 3개의 관련 상품 후보와 확인 사항을 보여준다. 산업·기술 변화 키워드가 발견되면 기존 상품 탐색과 별도로 `신규위험 갭 가설`을 만들고, 고객이 선택 동의한 경우에만 비식별 신호를 로컬 큐에 추가한다. 발표자는 양쪽 우상단의 사용자 전환으로 고객 경험과 실무자 유입 큐를 이어서 시연한다.

```text
고객 입력
  ├─ 생활 맥락 분류 → 상품 후보 → 공식 상품 페이지
  └─ 변화 신호 탐지 → 개인정보 마스킹 → 선택 동의
                                      ↓
                              로컬 신호 저장소
                                      ↓
                         실무자 대시보드 고객 신호 큐
```

## 구현 파일

- 고객 공개 웹 셸: `src/app/layouts/CustomerLayout.tsx`
- 사용자 전환: `src/shared/components/ModeSwitch.tsx`
- 고객 웹 페이지: `src/pages/customer-insight/CustomerInsightPage.tsx`
- 입력·결과 UI: `src/features/customer-insight/CustomerInsightStudio.tsx`
- 분석 규칙·마스킹: `src/features/customer-insight/recommendationEngine.ts`
- 공식 상품 메타데이터: `src/domain/product/catalog.ts`
- 신호 계약: `src/domain/risk/types.ts`
- 로컬 저장·이벤트: `src/domain/risk/customerSignalStorage.ts`

## 현재 데이터 흐름

1. 생애 단계, 상황 범주, 자유 서술, 도움 수준을 메모리에서 분석한다.
2. 상황 범주와 키워드에 따라 상품 카탈로그 후보를 점수화한다.
3. 후보 이유와 `계약 전 확인할 점`을 표시한다.
4. 신규위험 규칙에 맞으면 테마, 갭 가설, 실무자 질문을 생성한다.
5. 연구 공유 동의를 선택하고 버튼을 누른 경우에만 신호를 마스킹해 저장한다.
6. 같은 브라우저의 대시보드가 저장 이벤트를 받아 큐를 갱신한다.

## 의도적으로 하지 않는 것

- 보험료 계산
- 보장 확정, 인수 승인, 가입 권유 확정
- 약관 전체를 검색했다고 주장하는 것
- 고객 원문을 실무자에게 그대로 전달하는 것
- 하나의 고객 신호를 후보로 자동 승격하는 것
- 현대해상 계약 API 호출

## 운영 API로 교체할 경계

로컬 저장 구현을 다음 두 서비스로 분리한다.

### Customer Guidance API

- 승인된 상품 마스터와 판매 상태, 상품 문서 버전을 사용한다.
- 결과에 사용한 규칙/모델 버전과 상품 데이터 시점을 반환한다.
- 공식 상담·가입 채널로 넘길 때 고객 동의와 채널 추적 ID를 관리한다.
- 설명 가능성과 적합성·적정성 절차를 준수한다.

### Emerging Signal Intake API

- 원문 수신 최소화, 서버 측 비식별화, 보존기간, 삭제 정책을 적용한다.
- 동의 목적·문구 버전·철회 상태를 별도 원장으로 관리한다.
- k-익명성 등 승인된 최소 집계 기준 전에는 분석가 화면에 노출하지 않는다.
- 스팸, 중복, 조작 가능성을 평가하고 사람이 승격을 승인한다.

## 수용 기준

- 동의하지 않아도 상품 후보 결과는 동일하다.
- 결과마다 추천 이유와 공식 확인 지점이 있다.
- 민감정보 패턴이 신호 요약에 남지 않는다.
- 신호에는 개인 식별자 대신 테마, 맥락 범주, 시각, 갭 가설만 포함된다.
- 전송 성공·실패·중복 상태를 사용자에게 명확히 알린다.
- 운영 버전은 동의 철회와 신호 삭제를 처리한다.
