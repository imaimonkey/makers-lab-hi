# Step 3 · 위험 상세 시스템 프롬프트

`/risks/:riskId`의 위험 상세는 기사 원문에서 확인한 사실, 위험 해석, 점수, 추세, 근거, 판단 보류 이유를 한 화면에서 검토하는 실무자 워크벤치다. 이 디렉터리는 한 번의 거대한 생성을 요청하지 않고, 화면의 책임과 데이터 생명주기에 맞춰 기사 분석 LLM 프롬프트를 섹션별로 분리한다.

## 파일과 화면 책임

| 파일 | 화면·도메인 섹션 | 주요 출력 |
| --- | --- | --- |
| `01-risk-context-and-input.md` | 기사 원문·분석 입력 | 사실, 변화, 노출 대상, 손실 사건, 분석 메타데이터 |
| `02-risk-summary.md` | 위험 후보 헤더·위험 문장 | 후보 제목, 위험 문장, 노출 주체, 주요 손해, 상태 제안 |
| `03-assessment-scores.md` | `평가 요약`·`판단 상세` 지표 | 6개 평가값, 입력값, 계산식, AI 논리 코멘트 |
| `04-signal-trend.md` | `신호 추이` | 관측 시계열, 추세 판단, 변화율, 추세 불확실성 |
| `05-evidence-ledger.md` | `판단 자료`·근거 원장 | 근거 ID, 출처, 발췌, 연결 판단, 불확실성, 반증 |
| `06-decision-brief.md` | `현재 판단`·`다음 확인 항목` | 진행·보류·관찰 제안, 결정 이유, 다음 조사 과제 |
| `07-productization-review.md` | 보험상품화 종합 평가 | 상품·약관·법령·데이터 검토 질문과 게이트 제안 |
| `08-human-review-handoff.md` | 담당자 메모·검토 인계 | 역할별 질문, 미결 쟁점, 반증, 검토 기록 초안 |

각 파일은 독립 시스템 프롬프트로 사용할 수 있지만, 운영에서는 `01 → 05 → 03 → 04 → 06 → 07 → 08` 순서로 실행하고 서버가 ID와 버전을 연결한다.

## 공통 기사 입력

모든 프롬프트는 다음 입력 봉투를 전제로 한다. `body`가 없거나 원문 확보에 실패하면 요약·검색 결과만으로 사실을 만들지 않는다.

```json
{
  "article": {
    "articleId": "A-001",
    "clusterId": "CL-010",
    "title": "원문 기사 제목",
    "body": "확보된 기사 본문 전체",
    "sourceName": "출처명",
    "sourceUrl": "https://example.com/article",
    "publishedAt": "2026-07-29T09:00:00+09:00",
    "collectedAt": "2026-07-29T10:00:00+09:00",
    "contentStatus": "ready"
  },
  "priorArticles": [],
  "knownEvidenceIds": [],
  "knownRiskId": null,
  "knownRiskContext": null,
  "sourceAsOf": "2026-07-29T10:00:00+09:00",
  "promptVersion": "risk-detail-v1"
}
```

## 공통 출력·안전 규칙

- 출력은 설명 문장 없이 유효한 JSON 객체 하나만 반환한다. Markdown 코드 펜스와 추가 코멘트는 금지한다.
- 입력 원문에서 직접 확인한 사실과 LLM의 해석·가설을 서로 다른 키로 둔다. `fact`, `interpretation`, `hypothesis`, `needsVerification`을 섞지 않는다.
- 모든 사실성 문장은 `articleId`, 문장 번호 또는 `knownEvidenceIds`로 역추적할 수 있어야 한다.
- 입력에 없는 숫자, 사고 빈도, 손해액, 법령명, 판례, 기관, 상품명, 가입 수요, URL을 생성하지 않는다.
- 원문 URL이 없으면 URL을 추정하지 않고 `null`과 `원문 URL 확인 필요`를 반환한다.
- 검색 결과 부재는 보장 부재가 아니며, 기존 상품 검색 결과 부재는 보장되지 않음의 증거가 아니다.
- 단일 기사·단일 고객 신호로 신규위험 확정, 후보 자동 승격, 상품화 결정을 내리지 않는다.
- 점수는 우선순위 보조값이다. 점수의 입력·계산 버전·근거·한계를 함께 남긴다.
- `SAMPLE`은 화면 구조 검증용 값이다. 운영 데이터·공식 판단·보험료·보장·면책·가입 가능 여부로 표현하지 않는다.
- 고객 이름, 연락처, 주민등록번호, 상세 주소, 계약번호, 자유입력 원문 등 개인정보는 출력하지 않는다.
- 모델명, 프롬프트 버전, 분석 시각, 근거 스냅샷 시각은 서버가 기록한다. LLM은 입력된 값만 복사한다.

## LLM이 만들지 않는 값

경로 파라미터, canonical `riskId`, 최종 상태 저장, 담당자·권한, 감사 로그, 수집 성공 여부, 8개월 그래프용 보간값, 상품·약관의 실제 적용 여부, 보험료·인수 결과는 애플리케이션과 서버가 관리한다. LLM은 제안·근거·확인 필요 항목만 반환한다.
