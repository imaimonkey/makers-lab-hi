# 신규위험 전략 워크벤치

## 심사위원 데모 설명·용어·산식·예상 질문 최종본

> 목적: 보험·AI·데이터 배경이 없는 심사위원에게 화면의 의미를 설명하고, 화면에 표시된 용어와 숫자에 대한 날카로운 질문에 일관되게 답하기 위한 발표자용 문서입니다.

---

## 0. 발표자가 먼저 잡아야 할 한 문장

**이 서비스는 새로운 위험 신호를 보험상품 후보로 빠르게 구조화하고, 공개 근거·손해 규모·법률·보험 관점의 검토 질문을 한 흐름으로 연결하는 의사결정 지원 도구입니다.**

화면의 점수나 금액은 최종 인수 승인이나 보험료 확정값이 아닙니다. 공개자료와 명시적인 가정을 이용한 **1차 선별·검토용 결과**이며, 실제 상품화에는 내부 계약·사고·보험금·보험료 데이터와 계리·법무·보상 검증이 추가로 필요합니다.

### 20초 소개 멘트

“기존에는 새로운 위험을 발견해도 기사, 법령, 보험약관, 손해자료를 따로 찾아야 했습니다. 이 워크벤치는 위험 신호를 후보로 모으고, 시장성·손해 측정 가능성·보험사고 성립성·법률 부담·통제 가능성·집적손해를 같은 화면 흐름에서 비교하게 합니다. 그래서 숫자를 최종 결론으로 제시하는 것이 아니라, 다음 검토를 어디에 집중해야 하는지 빠르게 정하는 것이 핵심입니다.”

## 1. 심사위원에게 먼저 설명할 전체 구조

서비스의 흐름은 다음과 같습니다.

`위험 신호 발견 → 위험 후보 선별 → 위험 상세 분석 → 상품화·약관 검토 → 종합 리포트`

| 화면 | 심사위원에게 설명할 역할 | 핵심 질문 |
| --- | --- | --- |
| 위험 레이더(대시보드) | 최근 유입된 위험 신호와 우선 검토 후보를 한눈에 보는 시작 화면 | 무엇을 먼저 볼 것인가? |
| 위험 탐색 | 여러 후보를 분야·키워드·점수·PML 등으로 비교하는 화면 | 어떤 후보가 검토 가치가 큰가? |
| 위험 상세 | 한 후보의 발생 구조, 공식 근거, 손해·책임·기존 보험 연결을 깊게 확인하는 화면 | 이 위험을 보험 관점에서 어떻게 설계할 것인가? |
| 종합 리포트 | 검토 결과와 미확인 자료, 약관·상품화 질문을 문서 형태로 정리하는 화면 | 다음 의사결정과 담당 업무는 무엇인가? |

### 모드가 여러 개 보일 때

모드는 같은 위험 정보를 보는 **사용자 관점**을 바꾸는 장치입니다.

- 실무자·개발 모드: 위험 후보, 평가 기준, 근거, 검증 필요 항목을 중심으로 봅니다.
- 영업·상품화 모드: 잠재 계약자, 보장 공백, 상품 형태, 가입 의향 확인을 중심으로 봅니다.
- 고객·채널 인사이트 모드: 개인정보가 아닌 집계된 미충족 수요 신호를 확인합니다.

모드가 바뀌어도 위험을 임의로 확정하는 것이 아니라, 같은 위험을 담당자별 다음 행동에 맞게 보여주는 구조입니다.

### 1.1 현재 프로덕트의 실제 화면·코드 매핑

아래 내용은 첨부 Q&A의 가정이 아니라 현재 저장소의 라우터와 화면 컴포넌트 기준입니다.

| 실제 경로 | 현재 프로덕트에서 실행되는 화면 | 실제 구현상 역할 |
| --- | --- | --- |
| `/` | 위험 레이더(대시보드) | 최근 30일 KPI, 위험 신호, 상품화 우선 검토 TOP 5, 레이더 포착 근거, 국내·글로벌 보험 인사이트를 보여줍니다. |
| `/risks` | 위험 탐색 | `RiskExplorationLens`가 후보를 카테고리·검색·정렬하고, 왼쪽 후보 목록과 오른쪽 선택 후보 상세 평가를 함께 보여줍니다. |
| `/risks/:riskId` | 위험 상세 | `StandardRiskDetail`이 01~10 섹션, 원문 배지, 위험 심층 해설, 읽는 순서, 종합 리포트 연결을 제공합니다. |
| `/reports` | 종합 리포트 | 위험 후보의 근거, 보장 공백, 상품화 질문, PML·재무 추정과 후속 검토 결과를 리포트 흐름으로 연결합니다. |
| `/customer-insight` | 고객 인사이트 | 고객의 자유입력을 후보로 자동 승격하지 않고, 익명화·집계된 미충족 수요 신호를 실무 검토로 전달하는 별도 고객 화면입니다. |
| `/developer-test/*` | 개발·원문 연동 모드 | `src/article` 원문을 읽어 후보·법령·Step 2/3 분석 화면을 구성하는 검증용 경로입니다. |

### 1.2 실제 데이터가 화면으로 들어오는 경로

```text
src/article 원문
  → articleSourceData 로딩·그룹화·대표 문서 선택
  → RiskExplorationRecord로 변환
  → 위험 탐색 후보·법령 큐·원문 배지에 연결

큐레이션 데모 데이터(riskExplorationRecords)
  → 표준 후보·평가값·PML/TAM 표시값에 연결

고객·사내 유입 신호
  → localStorage 기반 집계 KPI에 연결
  → 단일 입력을 신규 위험 후보로 자동 승격하지 않음
```

따라서 현재 화면은 하나의 외부 운영 DB에서 모든 값이 실시간 계산되는 제품이 아닙니다. 큐레이션 데모 데이터, `src/article` 기반 원문 후보, 로컬 저장 유입 신호가 목적별로 합쳐지는 프로토타입입니다. 심사위원이 “모든 숫자가 같은 데이터베이스에서 계산되나요?”라고 물으면 **“현재는 아닙니다. 화면별 데이터 계약과 출처를 분리해 보여주는 단계이며, 운영판에서는 공통 RiskCandidate·EvidenceLedger·산식 버전 계약으로 통합할 계획입니다”**라고 답합니다.

### 1.3 위험 탐색에서 실제로 조작할 수 있는 기능

현재 `/risks`의 실무자 화면에는 다음 기능이 실제로 연결되어 있습니다.

- 카테고리: `전체`, `가계 위험`, `기업 위험`, `법률 및 규제 위험`, `사내 요청`, `고객 요청`
- 후보 검색: 위험명·기술·이슈뿐 아니라 요약, 태그, 분류, 보장 공백, 다음 조치, 출처명, 원문에서 구조화한 사실까지 검색
- 정렬: `AI 종합점수 순`, `시장성 순`, `우연성 순`, `법률 및 규제 리스크 순`, `PML 순`, `후보명 순`
- 후보 목록: 한 화면 5건 단위 페이지네이션, 선택한 후보는 오른쪽 상세 평가 패널에 연결
- 오른쪽 평가: 시장성, 손해 측정 가능성, 보험사고 성립성, 법적 책임·규제 부담, 통제 가능성, 손실 규모의 6개 판단 흐름
- 상세 연결: 선택 후보의 `위험 상세 >`를 눌러 `/risks/:riskId`로 이동

실무자 모드에서는 기간·출처 선택 필터가 개발 원문 연동 모드와 달리 비활성화될 수 있습니다. 개발 모드에서는 전체·최근 7일·최근 30일·최근 90일과 출처 필터가 원문 후보에 적용됩니다. 이는 화면에서 기능이 빠진 것이 아니라, 큐레이션 후보와 원문 수집 후보의 데이터 범위가 다르기 때문입니다.

### 1.4 법률 및 규제 위험 화면의 실제 구성

`법률 및 규제 위험` 카테고리를 선택하면 일반 후보 표가 아니라 법령 추적 패널이 열립니다.

1. 법령명·소관부처·내용 검색
2. 소관부처·기관 필터와 리스크 레벨 필터
3. 왼쪽 법령 목록과 기관명 배지
4. 선택 법령의 원문 확인 링크
5. `법령 기준 흐름`: 원문 기준 → 적용 조항·대상 → 보험료·책임 기준 → 예외·제재·시행 기준 → 상품화 후보 반영
6. `문서 기준`과 `상품화 연결` 카드
7. 연관 법원 판례 및 실제 손해 사례
8. 법령에서 확인되는 내용과 약관 설계가 필요한 내용을 나누는 `가입 의무 보험 약관 검토 조항`

여기서 법령 화면은 법령을 보험상품으로 자동 변환하는 기능이 아닙니다. 법령의 적용 대상·책임 주체·시행 기준을 약관 검토 항목으로 연결해, 상품개발·보상·법무 담당자가 다음 검증을 시작하도록 만드는 화면입니다.

### 1.5 위험 상세의 실제 10개 섹션

현재 표준 위험 상세는 다음 순서로 구성됩니다.

1. 해당 이슈의 내용과 맥락
2. 왜 보험 관점에서 주목해야 하나?
3. 위험 발생 구조
4. 정책·공식 자료
5. 손해와 비용의 확산 경로
6. 영향 대상과 책임 관계
7. 기존 보험·약관과의 연결
8. 종합 리포트로 넘길 상품화 질문
9. 위험 심층 해설
10. 활용 근거자료 원장

오른쪽 보조 카드에는 `이 위험을 읽는 순서`가 있고, 현재 01~05는 위험 발생 위치, 손해 확산, 책임 주체, 기존 보험 범위, 추가 확인자료의 순서로 구성됩니다. 아래에는 `종합리포트 >` 연결이 있습니다.

`위험 심층 해설`은 별도 숫자 점수를 새로 계산하는 화면이 아닙니다. `riskDetailContent`의 위험 서사, 연결된 정책·연구자료, 근거 원장, 사고·손해·책임 정보를 이용해 “신규 보험상품이 될 수 있는가”를 해설하고, 마지막에 잠정 상품화 판단·우선 검토 담보·핵심 인수조건·추가 필요자료를 제시합니다.

### 1.6 생성형 AI 저작권 상세는 실제 프로덕트의 특화 화면

현재 `RiskDetailPage`는 `generative-ai-copyright`를 일반 상세 컴포넌트가 아니라 `GenerativeAiCopyrightDetail`로 별도 렌더링합니다. 심사위원에게 생성형 AI 저작권 화면을 보여줄 때는 다음처럼 설명합니다.

- 상단: `기업 위험`, `원문 중심 분석`, `법률·책임 구조 이해` 배지와 위험 정의
- 요약: 학습 데이터·프롬프트·산출물 활용, 소송·방어비용·사용중단·재제작, AI 사업자·도입기업·사용자·권리자
- 공식 자료: 한국저작권위원회 안내서, 보험연구원 보고서, Swiss Re Institute, U.S. Copyright Office, 법제처 법령 원문
- 위험 구조: 저작물 수집·학습 → 프롬프트·생성 → 산출물 유사성 → 상업적 활용 → 침해 주장·분쟁
- 손해 경로: 저작권 침해 주장, 소송·방어비용, 콘텐츠 삭제·재제작, 계약상 배상책임, 평판·서비스 중단
- 기존 연결 보험: 전문직배상책임, 미디어배상책임, 사이버보험, 일반배상책임, 법률비용보험, 계약상 면책·보증
- 상품화 질문: 사고 정의, 고의·인지 가능 침해의 면책, 책임 주체, 보장 손해, 통제 수준을 확인
- 심층 해설: 8개 문단으로 학습·이용 단계, 법적 불확실성, 책임 확정 전 비용, 인간 창작 기여, 국내 규제, 기존 보험, 유리·불리한 요소, 현실적인 상품 형태를 연결
- 잠정 판단: 전면 보장보다 법률방어비용·감정비용·제한적 제3자 배상책임 중심의 특약·시범상품을 우선 검토

이 화면은 코드에 실제 원문 URL과 기관별 배지를 가지고 있다는 점에서, 단순히 첨부된 생성형 AI 설명문을 보여주는 페이지와 다릅니다. 다만 화면 하단도 명시하듯 법률 자문·침해 확정·보험금·보험료·PML을 제공하는 화면은 아닙니다.

## 2. 화면에 실제로 나오는 용어 정리

### 2.1 위험 탐색 화면

| 화면 용어 | 쉬운 뜻 | 발표 때의 정확한 설명 |
| --- | --- | --- |
| 위험 후보 | 보험 검토를 시작할 만한 위험 주제 | 아직 상품이 아니라, 보험화 가능성을 검토할 대상입니다. |
| 신규 위험 | 기존 위험 분류나 보장으로 충분히 설명하기 어려운 변화 | 사회·기술·법률·기후 변화에서 새롭게 커지는 위험 신호입니다. |
| 시장성 | 가입할 사람과 수요가 있을 가능성 | 수요 신호, 잠재 계약자, 시장 확장성, 지불 의향을 추가 검증해야 합니다. |
| 총도달가능시장(TAM) | 이론상 도달 가능한 전체 시장 규모 | 대상 시설·기업 수와 계약 단가를 곱한 상한 추정치입니다. 실제 매출 예측이 아닙니다. |
| SAM | 현재 상품·지역·채널로 접근 가능한 시장 | TAM에서 실제 사업 범위와 가입 조건으로 좁힌 시장입니다. |
| SOM | 단기간에 실제 확보를 목표로 할 수 있는 시장 | 판매 역량과 전환율을 반영한 실행 가능한 초기 시장입니다. |
| PML | 한 번의 큰 사고에서 발생할 수 있는 최대 손해 추정치 | 사고당 보상한도, 누적한도, 재보험 필요성을 검토하기 위한 시나리오 수치입니다. |
| 시장성 84점 | 시장 관련 여러 신호를 100점 척도로 표시한 탐색용 점수 | 수요조사로 확정된 시장점유율이 아니라, 현재 근거와 가정을 정규화한 점수입니다. |
| AI 종합점수 | 여러 평가항목을 한 숫자로 요약한 우선순위 지표 | 자동 승인점수가 아니라 후보를 먼저 볼 순서를 정하는 선별 지표입니다. |
| SAMPLE/샘플 표시 | 실제 내부 데이터가 아닌 데모 데이터라는 표시 | 공개자료·가정·프로토타입 수치를 실제 계약·보험금 데이터와 혼동하지 않기 위한 표시입니다. |
| 적용 기준일 | 법령·자료가 어느 시점 기준인지 보여주는 정보 | 데이터의 최신성과 재검증 필요성을 판단하는 기준입니다. |

### 2.2 위험 상세의 핵심 용어

| 화면 용어 | 뜻 | 확인해야 할 것 |
| --- | --- | --- |

## 3. 위험 탐색의 실제 평가항목과 산출식

위험 탐색에서는 후보를 빠르게 비교하기 위해 5점 척도의 원시 평가값을 사용합니다. 1점은 검토 근거가 약하거나 부담이 큰 상태, 5점은 보험화 관점에서 상대적으로 유리하거나 근거가 충분한 상태라는 의미입니다. 단, **법률·규제 리스크는 높을수록 부담이 큰 항목**이므로 다른 점수와 방향이 반대일 수 있습니다.

### 3.1 현재 데모의 8개 원시 평가항목

| 항목 | 무엇을 묻는가 | 점수의 해석 |
| --- | --- | --- |
| 수요(demand) | 누가 왜 가입할 가능성이 있는가? | 시장·수요 신호가 강할수록 높음 |
| 우연성(fortuity) | 사고가 고의가 아닌 우연한 사건으로 특정 가능한가? | 우연한 사고로 인정할 근거가 충분할수록 높음 |
| 집적(accumulation) | 한 사고에서 손해가 동시에 커질 수 있는가? | 위험이 크다는 뜻이지 좋은 점수라는 뜻은 아님 |
| 손해 측정 가능성(measurability) | 사고와 손해액을 객관적으로 확인할 수 있는가? | 증빙·손해 산정이 가능할수록 높음 |
| 역선택(adverse selection) | 위험이 큰 사람만 가입하려는 현상이 있는가? | 위험 신호가 강할수록 관리 부담이 큼 |
| 도덕적 해이(moral hazard) | 가입 후 관리 태만·고의·과다청구가 늘 수 있는가? | 위험 신호가 강할수록 관리 부담이 큼 |
| 데이터 신뢰도(data confidence) | 판단에 사용한 자료의 품질·최신성·연결성이 충분한가? | 원문·수치·사고자료가 확인될수록 높음 |
| 법률·책임 노출(legal exposure) | 법적 책임·규제·약관 불확실성이 얼마나 큰가? | 화면에서는 부담 수준을 표시하며, 높을수록 추가 법무 검토가 필요 |

### 3.2 위험 후보의 기본 종합점수

현재 큐레이션 후보의 탐색 정렬에 쓰는 기본 평균은 `calculateRiskExplorationScore`의 동일가중 평균입니다. 후보 목록 모델에는 이 점수의 의미가 `candidate-prioritization`, 척도가 `0-5`, 공식 버전이 `risk-screening.v1`, 기준일이 `2026-07-23`, `isMock: true`로 기록되어 있습니다. 즉 코드상으로도 최종 보험심사 점수가 아니라 후보 우선순위용 샘플임을 구분하고 있습니다.

```text
AI 종합점수(5점) =
(수요 + 우연성 + 집적 + 손해 측정 가능성
 + 역선택 + 도덕적 해이 + 데이터 신뢰도 + 법률·책임 노출) / 8
```

전기차 배터리 화재의 데모 입력값은 다음과 같습니다.

```text
(4.6 + 4.0 + 5.0 + 4.0 + 5.0 + 3.0 + 4.25 + 5.0) / 8
= 34.85 / 8
= 4.35625 ≈ 4.4/5
```

이 값은 “상품화 승인 확률 88%”가 아닙니다. 여러 항목을 같은 축에 놓고 우선순위를 정하는 **탐색용 평균**입니다. 실제 운영에서는 법률상 금지, 손해 측정 불가능, 피보험이익 부재처럼 하나만으로 보류해야 하는 항목을 평균으로 상쇄하지 않도록 게이트를 먼저 둬야 합니다.

다만 원문 연동 후보는 화면 경로가 다릅니다. `RiskExplorationLens`는 `record.articleId`가 있는 후보에 대해 `calculateProductizationScores(record.metricScores).total`을 정렬값으로 사용합니다. 따라서 큐레이션 후보의 8개 평균과 원문 기반 후보의 상품화 종합점수는 동일한 숫자 체계가 아닐 수 있습니다. 이것이 현재 프로덕트에서 후보에 따라 점수의 의미가 달라질 수 있는 실제 이유이며, 운영판에서는 후보 유형과 관계없이 하나의 `formulaVersion`을 사용하거나 화면에 산식명을 명시해야 합니다.

### 3.3 화면의 100점 시장성 점수

위험 탐색 카드에 표시되는 `A · 84점`은 기본 8개 평균과 같은 값이 아닙니다. 전기차 배터리 화재에 연결된 별도 정량화 프로토타입 값입니다.

```text
시장성 100점 = 100점 척도로 정규화한 시장성 평가값
등급 = 90점 이상 S, 75점 이상 A, 60점 이상 B, 그 미만 C
```

프로토타입에서는 수요 신호와 시장 자료를 이용해 84점을 표시합니다. 이상적인 운영 산식은 다음처럼 구성할 수 있습니다.

```text
시장성 점수 =
100 × [w1·시장규모 정규화
     + w2·잠재 계약자 수요
     + w3·지불 의향
     + w4·성장률
     + w5·보장 공백]
```

여기서 `w1~w5`의 합은 1이며, 실제 가중치는 설문·계약전환 데이터·과거 후보의 적중률로 보정해야 합니다. 현재 84점은 그 검증이 완료된 통계적 확률이 아니라 공개 근거를 이용한 1차 스크리닝 값입니다.

### 3.4 TAM·SAM·SOM 산식

```text
TAM = 전체 잠재 대상 수 × 대상당 연간 보험료
SAM = 실제 접근 가능한 대상 수 × 대상당 연간 보험료
SOM = SAM × 예상 계약 전환율
```

전기차 지하주차장 화재 예시에서 데모는 시설 단위 계약을 가정합니다.

```text
TAM = 대상 시설 수 17,189개 × 시설당 연간 보험료 가정
```

화면의 기준 TAM 약 121억 원/년, 추정 범위 약 65억~191억 원은 계약 수와 단가 가정의 곱입니다. 실제 판매액이 되려면 잠재 고객 인터뷰, 지불 의향, 판매 채널, 기존 보험과의 중복, 실제 계약 전환율을 확인해야 합니다.

### 3.5 PML 산식과 현재 전기차 예시

기본 개념은 다음과 같습니다.

```text
PML = 전손 차량 손해
    + 부분·그을림 피해 차량 손해
    + 시설 복구·긴급대응 비용
```

현재 데모의 기준 시나리오는 전소 87대, 부분 피해 783대를 가정합니다.

| 시나리오 | 화면 산식 | 결과 |
| --- | --- | ---: |
| 보수적 | 87대 × 3,000만 원 + 783대 × 50만 원 + 시설비 5억 원 | 약 35억 원 |
| 기준 | 87대 × 4,000만 원 + 783대 × 100만 원 + 시설비 10억 원 | 약 53억 원 |
| 확대 | 87대 × 5,000만 원 + 783대 × 200만 원 + 시설비 20억 원 | 약 79억 원 |

PML은 “반드시 발생할 손해”가 아니라 **사고 규모가 커졌을 때 회사가 감당해야 할 노출을 검토하는 시나리오**입니다. 실제 계리·재보험에서는 사고 발생률과 손해심도 분포를 결합해 연간 aggregate loss를 만들고, 예를 들어 다음과 같이 산출합니다.

```text
연간 총손해 L = Σ(사고별 손해액)
PML99.5 = L의 99.5% 분위수
TVaR99.5 = P(L이 PML99.5를 초과하는 경우의 평균 손해)
```

현재 35·53·79억은 이러한 확률분포 기반 PML99.5가 아니라 공개자료와 시나리오를 이용한 1차 추정입니다.

### 3.5.1 위험 탐색 카드에 실제 표시되는 정량화 어댑터

현재 후보 표의 핵심 열은 `시장성`, `PML`, `AI 종합점수`입니다. 내부 데이터에서는 시장성·우연성·법률 및 규제 리스크·PML을 `RiskCandidateQuantification` 계약으로 관리합니다.

| 화면 값 | 실제 코드상 표시 방식 | 심사위원에게 말할 내용 |
| --- | --- | --- |
| 시장성 | 원문 연동 후보는 상품화 점수의 시장성 축을 100점으로 환산하고, 큐레이션 후보는 후보별 프로토타입 값 또는 수요 5점×20을 사용 | 시장 규모 자체가 아니라 후보의 시장성 탐색 점수입니다. |
| 우연성 | 원시 점수 × 5점 표시, 사고 정의·고의·예측 가능성 확인 필요 | 보험사고 정의의 한 축입니다. |
| 법률 및 규제 리스크 | 원시 점수 × 5점 표시, 법률·책임 범위·약관 확인 필요 | 법적 결론이 아니라 법무 검토 부담 신호입니다. |
| PML | 후보별 연결 기준값, 또는 전손·부분손해·시설·긴급대응의 프로토타입 산식 | 실제 손해액이 아니라 상품화 검토용 금액 시나리오입니다. |
| TAM | 전기차 예시는 공통 재무추정의 TAM 범위, 원문 연동 후보는 국내 노출량·보험료 확인 필요, 그 외 후보는 시설 수×보험료 범위 | 판매 매출이 아니라 시장 규모 가정입니다. |

예를 들어 후보별 고정 프로토타입 표시에는 전기차 배터리 화재 `시장성 84점·PML 약 53억 원`, 생성형 AI 저작권 `78점·약 25억 원`, 집중호우·도시침수 `86점·약 500억 원` 등이 있습니다. 이 값들은 후보별 `attachmentPrototypeMetrics`에 연결된 데모 값이며, 모든 위험에 동일한 실제 통계 모델을 적용한 결과가 아닙니다.

PML 기준값이 없는 후보에는 코드가 전손 건수·단가, 부분손해 건수·단가, 시설·긴급대응비를 임시로 넣어 약 억 원 단위로 환산합니다. 따라서 심사위원이 다른 후보의 PML을 물으면 **“후보별 시나리오 입력이 다르고, 실제 손해자료가 연결되면 재산출하는 탐색용 값”**이라고 설명합니다.

### 3.6 상품화 종합점수의 현재 데모 산식

일부 화면과 종합 리포트에서는 8개 원시 평가값을 다시 시장성·PML·관리 가능성·법률준비도·근거점수로 묶어 5점으로 표시합니다. 현재 코드의 프로토타입 산식은 다음과 같습니다.

```text
시장성(100점) =
20 × (수요×0.45 + 도덕적 해이×0.15
       + 역선택×0.20 + 데이터 신뢰도×0.20)

PML(100점) =
20 × (우연성×0.45 + 집적×0.35 + 역선택×0.20)

관리 가능성(100점) = 100 - PML(100점)×0.55
법률 준비도(100점) = 100 - 법률·책임 노출×20
근거점수(100점) = 데이터 신뢰도×20

상품화 종합점수(100점) =
시장성×0.35 + PML×0.20 + 관리 가능성×0.15
 + 법률 준비도×0.15 + 근거점수×0.15

화면 표시값(5점) = 종합점수(100점) / 20
```

전기차 배터리 화재의 원시값을 그대로 넣으면 코드 반올림 기준으로 다음과 같이 나옵니다.

```text
수요 4.6, 우연성 4.0, 집적 5.0, 역선택 5.0,
도덕적 해이 3.0, 데이터 신뢰도 4.25, 법률·책임 노출 5.0

시장성 ≈ 87점
PML ≈ 91점
관리 가능성 ≈ 50점
법률 준비도 = 0점
근거점수 = 85점
종합 ≈ 68.9점 → 5점 환산 약 3.4/5
```

여기서 `PML`이라는 이름의 91점은 금액 PML 53억 원과 다른 **상품화 평가축**입니다. 한쪽은 위험 규모를 금액 시나리오로 표시하고, 다른 한쪽은 원시 평가값을 100점으로 정규화한 점수입니다. 발표 때 반드시 “금액 PML”과 “PML 평가점수”를 구분합니다.

또한 이 산식은 현재 데모의 탐색용 요약입니다. `법률 준비도 = 0점`처럼 법률 노출이 높은 후보가 평균으로 상쇄될 수 있으므로, 운영판에서는 법률·보험성 하드 게이트를 먼저 적용하고 점수는 그 통과 후보의 우선순위에만 사용해야 합니다.

아래 6개는 “보험상품이 될 수 있는가”를 단순 점수 하나가 아니라 서로 다른 질문으로 나누는 장치입니다.

| 우측 카드 | 현재 데모에서 보이는 값·해석 | 이상적인 산식·검증 |
| --- | --- | --- |
| 시장성과 수요 | 수요 4.6/5, 화면에서는 92% 또는 시장성 A·84점으로 표시될 수 있음 | 잠재 대상 수, 구매 의향, 지불 의향, 전환율, 보장 공백을 결합 |

### 4.1 시장성과 수요

이 카드는 “사람이 많이 관심을 보이는가”만 묻지 않습니다. 보험료를 내고 계약할 **구매 주체**가 있는지, 위험이 커지고 있는지, 기존 보장으로 해결되지 않는 불편이 있는지를 봅니다.

이상적인 수요모형은 다음과 같습니다.

```text
예상 계약 수 = 잠재 대상 수 × 가입 의향률 × 실제 전환율
시장 규모 = 예상 계약 수 × 연간 보험료
```

현재 92%는 전기차 배터리 화재 후보의 수요 신호를 데모에 표시한 값입니다. “시장 92%를 확보한다”는 뜻이 아닙니다.

### 4.2 손해 측정 가능성

보험은 사고가 났다는 주장만으로 지급할 수 없으므로, 사고와 손해를 재현 가능한 절차로 확인할 수 있어야 합니다.

```text
측정 가능성 점수 =
100 × [사고 관측성 + 손해자료 완전성
     + 원인·인과관계 식별성 + 금액 표준화 가능성]의 가중평균
```

확인 자료의 예시는 소방·경찰 사실확인원, 차량 수리·교체 견적, 시설 복구비, 손해사정 보고서, 기존 보험 지급내역입니다. 단, 자료가 있다는 사실만으로 손해액이 자동 확정되는 것은 아닙니다.

### 4.3 보험사고 성립성

보험사고 성립성은 점수보다 **통과 조건**으로 설명하는 것이 안전합니다.

```text
보험사고 성립성 =
피보험이익 존재
AND 우연한 사고
AND 실제 경제적 손해
AND 사고와 손해의 인과관계
AND 약관상 사고 특정 가능
```

하나라도 확인되지 않으면 “보험상품 성립”이라고 말하지 않고 `검토 필요` 또는 `보류`로 둡니다. 전기차 예시에서 우연성 4/5는 이 게이트 중 한 항목을 대리할 뿐, 보험성 전체를 보증하지 않습니다.

### 4.4 법적 책임과 규제 부담

법률·규제 점수가 높다는 것은 “불법 상품”이라는 결론이 아닙니다. 책임 주체, 의무보험 여부, 기존 보험과의 지급 순서, 개인정보·안전 규정, 약관 명확성 등을 더 확인해야 한다는 신호입니다.

이상적인 부담지수는 다음처럼 설계할 수 있습니다.

```text
법률 부담지수 =
w1·책임주체 불확실성
+ w2·규제 복잡성
+ w3·약관·면책 분쟁 가능성
+ w4·준수 비용
+ w5·집단·시스템 위험
```

화면의 원문 배지는 이 판단을 법률·감독기관·공공기관 원문으로 추적하기 위한 장치입니다. 원문 링크가 있다고 법률 자문이 완료되는 것은 아니며, 개정 시점과 적용 대상은 반드시 법무·준법 검토로 재확인해야 합니다.

### 4.5 통제 가능성

통제 가능성은 위험이 아예 없어지는 정도가 아니라, 예방·관리·조사·면책·자기부담금으로 손해의 빈도나 심도를 줄이고 구분할 수 있는 정도입니다.

```text
통제효과율 =
(통제 전 기대손해 - 통제 후 기대손해) / 통제 전 기대손해
```

현재 데모에는 이 식으로 산출한 통제효과율이 적용되어 있지 않습니다. 대신 도덕적 해이 3/5, 사고조사·관리 로그·면책기준 보완 같은 검토 신호를 보여줍니다. 심사위원이 “통제 가능성 60%인가요?”라고 물으면 **“아닙니다. 3/5는 원시 평가값이며 통제효과율로 읽으면 안 됩니다”**라고 답합니다.

### 4.6 손실 규모와 집적위험

```text
기대 연간 손해액 = 연간 사고빈도 × 사고당 평균 보장손해
집적손해 = 같은 사고·지역·시설·원인으로 발생한 여러 손해의 합
```

전기차 지하주차장처럼 한 시설에 차량과 시설이 함께 모이면 사고 빈도가 낮아도 한 번의 손해가 커질 수 있습니다. 따라서 PML은 보험료 하나만 정하는 값이 아니라 사고당 한도, 계약기간 총한도, 자기부담금, 재보험 출재를 함께 검토하는 값입니다.

## 5. 상품화·보험료 산식: 현재 데모와 이상적인 운영의 구분

### 5.1 이상적인 보험료 구조

```text
순보험료 = 기대 보험금
          + 대형사고·꼬리위험 비용
          + 재보험 비용
          + 사업비
          + 자본비용·불확실성 가산
          + 목표 이익
```

일반적으로 기대 보험금은 다음과 같이 구성합니다.

```text
기대 보험금 = Σ(위험군별 노출량 × 사고빈도 × 평균 보장손해)
```

실제 운영에서는 위험군별 노출량, 사고 발생률, 손해심도 분포, 중복보험, 구상 회수액, 재보험 구조를 분리해야 합니다.

### 5.2 현재 데모의 Base 가격 시나리오

현재 상품개발 프로토타입은 기준 PML 53억 원에 다음 가정을 연결합니다.

```text
연간 사고확률 = 0.001 = 0.10%
평균 손해심도 = PML의 1.2%
꼬리위험 가산율 = PML의 0.00025%
목표 손해율 = 60%
사업비 = 15%
불확실성 가산 = 8%
재보험 비용률 = PML의 0.0002%
```

코드상 원 단위 계산은 천 원 단위로 반올림합니다.

```text
통상 기대손해
= 5,300,000,000 × 0.001 × 0.012
= 63,600원

꼬리위험 가산
= 5,300,000,000 × 0.0000025
≈ 13,250원

예상 연간 손해액
= 63,600 + 13,250
= 76,850원

재보험 비용
= 5,300,000,000 × 0.000002
≈ 10,600원

제안 보험료
= 76,850 / 0.60
 + 10,600
 + 76,850 × (0.15 + 0.08)
≈ 156,359원
→ 천 원 단위 반올림: 약 156,000원
```

화면의 제안 보험료가 실제 판매 보험료라는 뜻은 아닙니다. 사고확률·평균 손해심도·사업비·재보험료가 모두 프로토타입 가정이고, 내부 손해율과 요율 검증을 거치지 않았기 때문입니다.

### 5.3 한도·자기부담금·재보험

현재 Base 시나리오의 연결 방식은 다음과 같습니다.

```text
사고당 제안 한도 = PML × 75%
= 53억 × 0.75 ≈ 39.75억 원

계약기간 총한도 = 사고당 제안 한도 × 1.5
≈ 59.63억 원

자기부담금 = 예상 연간 손해액 × 35%
≈ 2.7만 원
```

PML 53억 원이 회사 보유한도 30억 원보다 크므로 재보험을 “권고”로 표시합니다. 이 역시 최종 출재 결정이 아니라 보유한도·손해분포·재보험 조건을 추가 검토하라는 신호입니다.

## 6. 심사위원 예상 질문과 답변

답변은 항상 **주장 → 근거 → 한계 → 다음 검증** 순서로 합니다.

### Q1. 이 서비스가 기존 대시보드와 다른 점은 무엇인가요?

**답변:** 기존 대시보드는 지표를 보여주는 데 강합니다. 이 서비스는 위험 신호를 후보로 만들고, 시장·손해·보험성·법률·통제·집적위험을 보험 검토 질문으로 연결하며, 각 판단의 원문과 다음 확인자료까지 제시합니다. 따라서 핵심 산출물은 점수 자체가 아니라 “이 후보를 다음 단계에서 무엇으로 검증할 것인가”입니다.

### Q2. AI가 상품화 가능 여부를 결정하나요?

**답변:** 결정하지 않습니다. AI는 문서에서 위험·대상·손해·책임·근거를 구조화하고, 비교 가능한 검토 지표와 후속 질문을 만듭니다. 상품화 여부는 상품개발·계리·보상·법무·재보험 담당자의 검증과 승인으로 결정합니다. 화면의 `검토 필요`, `추가자료 필요`, `조건부` 상태가 바로 이 인간 검토 경계를 보여줍니다.

### Q3. 화면의 4.4/5, 84점, 92%는 서로 왜 다른가요?

**답변:** 서로 다른 지표입니다. 4.4/5는 8개 원시 평가항목의 평균인 탐색용 종합점수입니다. 84점은 시장성 100점 프로토타입 값이고, 92%는 수요 신호 표시값입니다. 세 값은 같은 의미의 확률이 아닙니다. 실제 운영에서는 `metricId`, `scale`, `formulaVersion`, `meaning`, `sourceAsOf`, `isSample`을 데이터 계약에 포함해 혼동을 막겠습니다.

### Q4. 그 점수의 가중치는 누가 정했나요? 통계적으로 검증됐나요?

**답변:** 현재 데모의 가중치는 업무 흐름을 보여주기 위한 설계 가정이며, 통계적으로 학습·검증된 보험료 요율이 아닙니다. 운영 전에는 과거 후보의 적중·보류·상품화 결과를 라벨로 만들고, 전문가 판단과 비교하며, 민감도·백테스트·캘리브레이션을 수행해야 합니다. 검증 전에는 점수를 예측확률처럼 말하지 않겠습니다.

### Q5. 8개 항목을 평균내면 법률 위험이 다른 항목에 묻히지 않나요?

**답변:** 맞는 지적입니다. 현재 평균은 후보를 빨리 비교하기 위한 탐색용 요약입니다. 실제 심사 엔진은 평균 전에 하드 게이트를 적용해야 합니다. 예를 들어 피보험이익이 없거나, 손해를 객관적으로 측정할 수 없거나, 법률상 보장이 불가능한 경우에는 평균점수와 관계없이 보류합니다. 평균은 우선순위, 게이트는 적격성 판단으로 분리하겠습니다.

### Q6. 시장성 84점이면 시장의 84%를 확보할 수 있다는 뜻인가요?

**답변:** 아닙니다. 84점은 시장 근거와 수요 신호를 100점 척도로 정규화한 탐색용 점수입니다. 시장점유율이나 전환율이 아닙니다. 실제 시장성은 잠재 시설 수, 가입 의향, 지불 의향, 예상 전환율, 판매 채널을 조사해서 `대상 수 × 전환율 × 단가`로 다시 산출해야 합니다.

### Q7. TAM 약 121억 원은 실제 매출인가요?

**답변:** 아닙니다. TAM은 대상 시설 수와 연간 보험료 가정을 곱한 이론상 시장 규모입니다. 실제 매출은 SAM과 SOM을 거쳐야 하며, 가입 의향·판매 가능성·기존 보험 중복·보험료 수용 수준을 반영해야 합니다. 현재 값은 공개자료 기반 1차 추정입니다.

### Q8. PML 약 53억 원은 실제로 53억 원을 지급한다는 뜻인가요?

**답변:** 아닙니다. 전소 차량 87대, 부분 피해 차량 783대, 시설비 10억 원이라는 기준 시나리오의 합입니다. 보수적·확대 시나리오는 약 35억~79억 원입니다. 실제 PML은 시설별 노출량과 손해 분포를 연결해 다시 계산하고, 지급액은 약관상 보상 대상·한도·자기부담금·기존 보험 지급액에 따라 달라집니다.

### Q9. PML은 확률값인가요?

**답변:** 현재 화면의 35·53·79억 원은 확률분포 기반 PML99.5가 아니라 시나리오 추정값입니다. 이상적인 운영에서는 연간 총손해 분포의 99.5% 분위수나 TVaR를 산출합니다. 따라서 데모에서는 “PML 시나리오”라고 말하고, “규제자본용 PML이 확정됐다”고 말하지 않습니다.

### Q10. 보험사고가 성립한다는 근거는 무엇인가요?

**답변:** 보험사고는 피보험이익, 우연성, 실제 경제적 손해, 인과관계, 약관상 사고 특정 가능성을 모두 확인해야 합니다. 전기차 화재 예시의 우연성 4/5는 이 중 한 항목의 대리 지표입니다. 화면의 `보험상품 성립 요건`은 추가 검증을 안내하는 구조이지 법적 결론을 대신하지 않습니다.

### Q11. 법률·규제 리스크가 높은데 왜 상품 후보로 남겨두나요?

**답변:** 높은 법률 노출은 상품화 가능 판정이 아니라 법무·준법 검토 우선순위가 높다는 뜻입니다. 책임 주체, 의무보험 여부, 기존 보험 지급 순서, 약관의 보장·면책 범위를 원문과 연결해 확인한 뒤 설계 가능한 부분과 보류할 부분을 나눠야 합니다. 위험을 숨기지 않고 상품화 조건으로 드러내는 것이 이 화면의 목적입니다.

### Q12. 기존 자동차보험·화재보험과 무엇이 다른가요?

**답변:** 기존 보험이 전혀 보장하지 않는다고 단정하지 않습니다. 기존 보험은 피보험자, 법률상 책임, 보험목적, 가입금액, 면책에 따라 일부 손해를 보장할 수 있습니다. 이 후보는 책임 확정 전 손해, 한도 초과, 시설·제3자 손해, 기존 보험 적용 후 잔여 직접손해처럼 보장 공백이 생길 수 있는 구간을 비교하는 것입니다. 최종 중복 여부는 약관 대조가 필요합니다.

### Q13. 사고 원인이 확정되지 않으면 보험금을 지급할 수 있나요?

**답변:** 그것은 약관 설계의 핵심 쟁점입니다. 가능한 구조는 지급요건을 객관화하고, 책임 확정 전 약정된 범위에서 선지급한 뒤 책임자에게 구상하는 방식입니다. 다만 선지급 범위, 발화 차량 자체 손해, 중복보험 차감, 고의·불법 개조 면책을 약관과 보상 절차로 확정해야 합니다.

### Q14. 통제 가능성 3/5는 손실을 60% 줄인다는 뜻인가요?

**답변:** 아닙니다. 3/5는 도덕적 해이·관리 통제에 관한 원시 평가값입니다. 손실 감소율이 아닙니다. 이상적인 통제효과율은 `(통제 전 기대손해 - 통제 후 기대손해) / 통제 전 기대손해`로 실제 사고 전후 데이터가 있어야 산출할 수 있습니다.

### Q15. 공개자료만으로 보험료를 제시하는 것이 위험하지 않나요?

**답변:** 맞습니다. 그래서 화면의 보험료는 `프로토타입 시나리오`로 표시해야 하며 실제 판매가격으로 제시하지 않습니다. 현재는 PML·공개 사고자료·가정한 사고확률·손해심도를 연결해 산식의 형태를 보여줍니다. 운영 전에는 내부 계약 수, 실제 지급보험금, 위험노출량, 사업비, 재보험료, 손해율을 연결해 계리 검증을 해야 합니다.

### Q16. Base 보험료 약 15만 6천 원은 어떻게 나왔나요?

**답변:** 기준 PML 53억 원에 사고확률 0.10%, 평균 손해심도 1.2%, 꼬리위험 가산을 적용해 예상 연간 손해액 7만 6,850원을 계산합니다. 이를 목표 손해율 60%로 나누고 재보험 비용 1만 600원, 사업비 15%, 불확실성 8%를 더해 약 15만 6,359원, 화면에서는 천 원 단위로 약 15만 6천 원으로 표시합니다. 모든 입력이 가정값이므로 실제 보험료가 아닙니다.

### Q17. 보험료가 너무 낮아 보이는데요?

**답변:** 그럴 수 있습니다. 현재 시나리오는 시설 단위 계약의 단가·사고확률·손해심도를 단순화한 데모입니다. 실제 가격에는 계약별 노출량, 최소보험료, 고정 사업비, 위험군별 요율, 재보험료, 자본비용, 손해분포를 넣어야 합니다. 심사에서는 금액의 절대값보다 입력값을 공개하고 재계산 가능한 구조인지가 중요합니다.

### Q18. AI가 원문을 잘못 요약하거나 출처를 잘못 연결하면 어떻게 하나요?

**답변:** 원문 링크·기관명·문서 기준일·근거 ID를 함께 남기고, AI 요약과 원문 사실을 분리해야 합니다. 법률·보험 판단은 원문 확인 상태와 불확실성을 표시하며, 사람이 원문을 확인하지 않은 경우 확정 표현을 하지 않습니다. 운영 단계에서는 출처 중복 제거, 원문 변경 감지, 인용 구간 저장, 검토자 승인 이력을 추가합니다.

### Q19. 기사 하나가 위험 후보로 자동 승격될 수 있나요?

**답변:** 안 됩니다. 기사는 신호일 뿐입니다. 다중 출처 교차검증, 최소 집계 기준, 중복 기사 제거, 영향 대상·손해·책임 구조 확인, 사람의 검토를 거쳐 후보로 올려야 합니다. 고객 단일 입력도 자동으로 신규위험으로 승격하지 않고 개인정보를 제거한 집계 신호만 사용합니다.

### Q20. 고객 데이터와 개인정보는 어떻게 보호하나요?

**답변:** 분석가 후보에는 이름·연락처·주민등록번호·상세 주소·자유입력 원문을 저장하지 않고, 익명화·최소 집계된 신호만 연결하는 원칙입니다. 실제 운영에는 접근권한, 보존기간, 감사로그, 목적 외 이용 통제, 모델 입력 차단 정책을 별도로 구현하고 검증해야 합니다. 현재 로컬 데모의 저장 방식과 운영환경의 보안 통제를 동일하게 말하면 안 됩니다.

### Q21. 이 프로젝트의 실제 사업 가치는 무엇인가요?

**답변:** 아직 보험료 매출이나 손해율 개선을 증명한 단계는 아닙니다. 현재 입증하는 가치는 후보 발굴부터 근거 확인, 보험성 평가, 상품화 후속 업무까지의 탐색 시간을 줄이고, 부서마다 흩어진 검토 질문을 같은 구조로 남기는 것입니다. 운영 도입 후에는 후보 발굴 소요시간, 원문 검증시간, 부서간 재작업 횟수, 검토 후보의 실제 전환율을 KPI로 측정해야 합니다.

### Q22. 경쟁 서비스와 비교했을 때 모방하기 어려운 부분은 무엇인가요?

**답변:** 단순 뉴스 수집이나 점수화만으로는 차별화가 약합니다. 이 프로젝트의 핵심은 위험 신호를 보험의 언어인 보장 공백·손해 측정·책임·약관·PML·재보험 검토로 변환하고, 각 판단을 원문과 다음 담당 업무에 연결하는 운영 프레임입니다. 경쟁력은 현재 화면의 디자인보다 데이터 계약, 근거 이력, 평가 일관성, 실제 업무 결과로 검증해야 합니다.

### Q23. 가장 큰 현재 한계는 무엇인가요?

**답변:** 내부 계약·사고·보험금 데이터가 연결되지 않았고, 시장성·PML·보험료 수치 일부가 공개자료와 시나리오 가정에 기반합니다. 또한 평가 가중치가 통계적으로 검증된 상태가 아닙니다. 그래서 제품의 현재 역할은 최종 심사 엔진이 아니라 **검증할 후보와 자료를 빠르게 구조화하는 실무 프로토타입**입니다.

### Q24. 다음 단계에서 가장 먼저 확보할 데이터는 무엇인가요?

**답변:** 첫째 실제 계약·노출량, 둘째 사고 건수와 사고당 손해액, 셋째 지급보험금과 손해율, 넷째 기존 약관·중복보장, 다섯째 잠재 고객의 가입 의향과 지불 의향입니다. 이 자료가 있어야 후보 점수의 가중치, PML 분포, 보험료·한도·재보험 조건을 검증할 수 있습니다.

### Q25. 지금 당장 상품을 출시하자는 결론인가요?

**답변:** 아닙니다. 결론은 “상품 검토를 시작할 가치가 있고, 동시에 어떤 조건을 검증해야 하는지가 명확하다”입니다. 현재 전기차 배터리 화재 후보의 잠정 방향은 보장 공백과 시장 신호는 긍정적이지만, 실제 수요·PML·약관·법률·내부 손해자료 확인이 필요한 조건부 검토입니다.

## 7. 심사위원이 숫자를 집요하게 물을 때의 답변 순서

1. **그 숫자가 무엇인지 먼저 말합니다.** 점수인지, 비율인지, 금액인지, 시나리오인지 구분합니다.
2. **산식과 입력값을 말합니다.** 화면에 보이는 결과를 숨기지 않고 계산 경로를 제시합니다.
3. **출처와 가정을 분리합니다.** 원문에서 확인한 사실, 프로젝트 가정, 모델 해석을 따로 말합니다.
4. **현재 적용 수준을 말합니다.** 데모 표시인지, 실제 데이터 기반인지, 통계 검증인지 구분합니다.
5. **다음 검증을 말합니다.** 어떤 내부 데이터·법무 검토·계리 검증이 필요한지 답합니다.

### 예시 답변

“약 53억 원은 실제 지급액이 아니라 기준 PML 시나리오입니다. 전소 87대×4천만 원, 부분 피해 783대×100만 원, 시설비 10억 원을 합산한 값입니다. 공개자료와 가정에 기반하므로 현재 확정 PML이 아니며, 실제 운영에서는 시설별 노출량·사고분포·손해사정 데이터를 연결해 재산출하겠습니다.”

## 9. 마지막 한 장에 넣을 결론

### 이 프로젝트가 보여주는 것

- 새로운 위험을 뉴스나 문서의 단편이 아니라 **보험 검토 가능한 후보**로 구조화합니다.
- 시장성과 수요, 손해 측정 가능성, 보험사고 성립성, 법률·규제 부담, 통제 가능성, 손실 규모·집적위험을 분리해서 봅니다.
- TAM·PML·보험료 같은 수치를 산식과 가정으로 연결해 **다시 계산 가능한 판단**으로 만듭니다.
- 기관명 원문 링크와 근거를 붙여 AI 요약을 사람이 검증할 수 있게 합니다.
- 현재 결론을 확정하지 않고, 상품개발·계리·보상·법무·재보험이 다음에 확인할 자료를 명확히 합니다.

### 최종 발표 문장

**“이 화면의 숫자는 결론을 대신하는 숫자가 아니라, 어떤 위험을 먼저 검증하고 어떤 근거가 더 필요한지를 알려주는 공통 언어입니다. 우리는 AI로 판단을 자동화하려는 것이 아니라, 새로운 위험을 보험상품 검토가 가능한 구조로 바꾸고 사람의 최종 판단을 더 빠르고 추적 가능하게 만들고자 합니다.”**
