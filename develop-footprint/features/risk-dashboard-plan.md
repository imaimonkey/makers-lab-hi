# 신규위험 통합 대시보드 기획안

기획 범위: 실무자 워크벤치의 `/` 화면만 다룬다. 이 문서는 화면의 목적, 정보 구조, 표시 문구, 상태 처리와 다음 구현 의존성을 정의한다.

## 1. 화면 한 줄 정의

최근 관측에서 무엇이 변했는지 확인하고, 오늘 검토할 위험 후보와 데이터 보강 과제를 바로 선택하는 실무자용 상황판이다.

대시보드는 위험을 자동 확정하는 화면이 아니다. `신호 → 후보 → 평가`로 넘어가기 위한 우선순위와 근거 상태를 보여주며, 최종 판단은 담당자가 한다.

## 2. 대상 사용자와 핵심 질문

### 주 사용자

- 신규위험 탐색 실무자
- 위험 후보를 배정·검토하는 리더
- 데이터, 법무·준법, 상품개발 담당자

### 대시보드에서 1분 안에 답해야 하는 질문

1. 최근 무엇이 평소보다 크게 변했는가?
2. 지금 상세 평가를 시작하거나 다시 볼 후보는 무엇인가?
3. 신호가 오래됐거나 수집에 실패한 채널은 어디인가?
4. 고객 채널에서 최소 집계 기준을 통과한 반복 위험은 무엇인가?
5. 다음 행동의 담당자와 근거가 비어 있지는 않은가?

## 3. 범위와 제외 범위

### 포함

- 신호 최신성, 변화량, 절대량의 요약
- 우선 검토 후보 큐
- 신호 수집 채널과 데이터 품질 상태
- 검토 파이프라인의 병목
- 비식별·최소 집계 고객 신호
- 공식 출처 확인이 필요한 법령·정책 변화 알림
- `/risks`와 `/risks/:riskId`로 이어지는 다음 행동

### 대시보드에서 하지 않음

- 후보를 자동으로 신규위험으로 확정
- 상품의 보장, 면책, 보험료, 가입 가능 여부를 단정
- 고객 원문, 이름, 연락처, 상세 주소 등 개인정보 표시
- 개별 고객 신호 하나를 후보로 승격
- 위험 상세 평가, 의견 이력, 종합 리포트 작성

## 4. 화면 정보 구조

```text
페이지 헤더·기준 시각
  └ 핵심 현황 4개
      ├ 최근 7일 신규 신호
      ├ 검토 대기 후보
      ├ 근거·법령 확인 필요
      └ 집계 고객 신호
  └ 오늘의 우선 검토 후보 ───── 신호 추이
  └ 검토 파이프라인 ────────── 수집 채널 상태
  └ 고객 신호 집계 큐 ───────── 법령·정책 변화
```

데스크톱에서는 좌우 2열을 사용하되 우선 검토 후보가 가장 넓어야 한다. 작은 화면에서는 위 순서대로 한 열로 쌓고, 표는 카드형 행 또는 가로 스크롤로 제공한다.

## 5. 섹션별 상세 기획

### 5.1 페이지 헤더

화면 제목은 기존 내비게이션과 맞춰 `위험 레이더`를 사용한다.

- 제목: `위험 레이더`
- 설명: `최근 변화와 근거 상태를 한눈에 보고, 오늘 검토할 위험 후보를 선택하세요.`
- 보조 상태: `실무자 워크벤치`
- 기준 시각: `마지막 집계 2026.07.24 09:30 KST` 형식
- 데이터 표시: `실제 데이터` 또는 `SAMPLE · 구조 검증용 예시 데이터`
- 새로고침 버튼: `데이터 새로고침`

기준 시각은 페이지가 열린 시각이 아니라 데이터가 생성·수집된 시각이어야 한다. 대시보드 전체의 기준 시각과 각 카드의 개별 최신 시각이 다르면 카드에 따로 표시한다.

권장 안내 문구:

> 이 화면은 신호와 후보의 검토 우선순위를 돕습니다. 상품화 여부와 보장 범위는 공식 문서 확인 및 담당자 검토가 필요합니다.

### 5.2 핵심 현황 카드 4개

카드의 숫자만 비교하지 않도록 `정의`, `기준 기간`, `변화량`, `출처 최신 시각`을 함께 보여준다.

| 카드 제목 | 숫자의 의미 | 보조 문구 | 클릭 후 행동 |
| --- | --- | --- | --- |
| 최근 7일 신규 신호 | 이전 기준 기간에 없고 이번 기간에 처음 관측된 신호 수 | `전주 대비 +8건` | 신호 기준으로 후보 목록 열기 |
| 검토 대기 후보 | 사람의 검토가 아직 끝나지 않은 후보 수 | `담당자 미지정 3건` | `/risks`에서 검토 대기 필터 |
| 근거·법령 확인 필요 | 최신 근거가 부족하거나 법령·정책 확인이 필요한 후보 수 | `가장 오래된 항목 5일 전` | 확인 필요 후보 목록 열기 |
| 집계 고객 신호 | 최소 집계 기준을 통과해 실무자 검토 큐에 들어온 범주 수 | `개별 고객 정보 미포함` | 집계 신호 큐 보기 |

카드 문구 예시:

- 정상 변화: `전주 대비 8건 증가`
- 변화 없음: `전주와 동일`
- 비교 불가: `기준 기간 데이터 부족`
- 최신성 경고: `마지막 집계 26시간 전`
- 데이터 미연동: `집계 API 연결 전`

`신규 위험 후보`와 `신규 신호`를 같은 뜻으로 사용하지 않는다. 신호는 관측 단위이고 후보는 반복성·손실·노출 등을 검토한 뒤 사람이 다루는 작업 단위다.

### 5.3 오늘의 우선 검토 후보

대시보드의 주 행동 영역이다. 기본 3건을 보여주고 `전체 후보 보기`로 `/risks`에 이동한다.

행 구성:

- 순번
- 후보명
- 한 줄 위험 정의: `변화 원인 → 노출집단 → 예상 손실`
- 신호 강도
- 근거 신뢰도
- 다음 검토일 또는 지연 일수
- 우선순위 이유 태그
- `상세 평가 열기`

우선순위 이유 태그 예시:

- `신호 급증`
- `근거 최신성 경고`
- `법령 확인 필요`
- `재검토일 도래`
- `담당자 미지정`

샘플 화면 문구:

> 전기차 배터리 화재와 충전시설 책임  
> 배터리·충전 인프라 확산 → 운전자·충전사업자 → 화재·대인·영업중단 손실  
> 신호 강도 82 · 근거 6건 · 다음 검토 2026.07.25

점수 하나로 순위를 고정하지 않는다. 정렬 근거는 `신호 변화`, `근거 신뢰도`, `손실 명확성`, `상품화 적합성`을 분리해 표시하고, 종합 정렬을 제공할 경우 계산 버전과 가중치를 확인할 수 있어야 한다.

### 5.4 신호 추이

최근 12주 또는 7일의 변화 추이를 주제별로 비교한다.

필수 조작:

- 주제 선택: `전체`, `AI·디지털`, `기후·에너지`, `모빌리티`, `플랫폼 노동`
- 지표 전환: `절대량` / `기준선 대비 변화율`
- 기간 전환: `7일`, `30일`, `12주`
- 차트 포인트 hover 및 키보드 접근 가능한 상세 표

차트 상단 설명:

> 변화율은 선택한 기준 기간과 비교한 값입니다. 절대량이 많다고 위험도가 높다는 뜻은 아닙니다.

차트 하단에 다음을 표시한다.

- 기준 기간
- 마지막 관측 시각
- 포함된 출처 수
- 중복 제거 기준 또는 클러스터 버전

차트가 없어도 같은 데이터를 표로 읽을 수 있어야 한다. 색상만으로 주제를 구분하지 않고 범례의 텍스트와 패턴·라벨을 함께 사용한다.

### 5.5 검토 파이프라인 현황

현재 어느 단계에 일이 쌓였는지 보여주는 보조 상황판이다.

```text
수집 → 반복성·중복 확인 → 위험 후보화 → 근거·법령 확인 → 상품성 검토
```

각 단계에는 `현재 건수`, `전 기간 대비 변화`, `가장 오래된 대기 시간`을 표시한다.

병목 예시:

> 현재 병목: 법령·손해 데이터 보강  
> 법령 확인 필요 5건, 가장 오래된 대기 3일  
> 자동 점수는 우선순위 보조이며 최종 결정은 실무자가 수행합니다.

단계별 버튼은 해당 조건의 후보 목록으로 이동한다. 후보를 다음 단계로 자동 이동시키는 버튼은 제공하지 않는다.

### 5.6 수집 채널 상태

행 필드:

- 채널명
- 채널 역할
- 마지막 성공 시각
- 지연 시간
- 최근 수집 건수
- 품질 상태
- 실패·보류 사유
- 담당자 또는 재수집 요청 상태

상태 라벨:

- `정상`: 예정 주기 안에 수집·검증 완료
- `지연`: 예정 주기를 넘겼으나 이전 데이터 사용 가능
- `확인 필요`: 수집은 되었지만 품질 검사가 필요한 상태
- `실패`: 최신 수집에 실패해 데이터 공백이 있는 상태

샘플 행:

> 법령·정책·판례 · 책임·제도 확인 · 마지막 성공 2시간 전 · 19건 · 확인 필요  
> 최근 개정 문서의 원문 링크 검증 대기

채널 장애가 있어도 대시보드 전체를 실패 화면으로 바꾸지 않는다. 해당 채널 카드만 경고하고 마지막 정상 시각을 유지한다.

### 5.7 비식별 고객 신호 집계 큐

고객 채널에서 들어온 신호 중 운영 기준을 통과한 범주만 보여준다. 고객 원문이나 단건 내용은 표시하지 않는다.

표시 필드:

- 집계 범주명
- 최소 집계 기준 충족 여부
- 관측 기간
- 반복 건수 구간: 예 `10~19건`
- 관련 위험 주제
- 검토 상태
- 집계 기준 버전

표시 문구:

> 고객 신호는 단건으로 위험 후보가 되지 않습니다. 최소 집계 기준과 중복 확인, 실무자 검토를 통과한 범주만 표시합니다.

빈 상태:

> 아직 검토 가능한 집계 고객 신호가 없습니다. 고객 원문은 이 화면에 저장하거나 표시하지 않습니다.

현재 로컬 데모에서 전달된 신호는 `SAMPLE`로 명시하고, 운영 연동 전에는 실제 집계 데이터처럼 보이지 않게 한다.

### 5.8 법령·정책 변화

공식 출처 확인이 필요한 변화만 보조 목록으로 표시한다.

행 필드:

- 기관명
- 문서 제목
- 발행일·수집일
- 연결 후보 또는 주제
- 예상 영향
- 원문 확인 상태

권장 문구:

> 법령·정책 변화는 위험 신호일 수 있지만, 적용 여부와 책임 범위는 원문 및 내부 검토를 거쳐 확정합니다.

공식 원문 링크가 없는 항목은 `출처 확인 대기`로 표시하고 확정적 표현을 쓰지 않는다.

## 6. 버튼·링크 문구

| 위치 | 기본 문구 | 보조 문구 |
| --- | --- | --- |
| 헤더 | `데이터 새로고침` | `마지막 집계 시각 보기` |
| 후보 카드 | `상세 평가 열기` | `근거 6건` |
| 후보 패널 | `전체 후보 보기` | `필터 유지` |
| KPI 카드 | `검토 대기 보기` | `조건 3개 적용됨` |
| 채널 상태 | `상태 상세` | `재수집 요청` |
| 고객 신호 | `집계 기준 보기` | `개인정보 미포함` |
| 법령 목록 | `원문 확인` | `공식 출처` |

`확정`, `보장됨`, `가입 가능`, `보험료 산출 완료`처럼 상품 결정을 완료한 것으로 오해할 수 있는 표현은 사용하지 않는다.

## 7. 데이터 계약 제안

구현 시 페이지 내부 타입을 만들지 않고 `src/domain`의 공통 계약으로 추가한다. 대시보드가 직접 `localStorage`를 읽지 않도록 어댑터를 둔다.

```ts
type DashboardSnapshot = {
  summary: {
    newSignals: MetricSummary
    reviewQueue: MetricSummary
    evidenceAttention: MetricSummary
    customerAggregates: MetricSummary
  }
  priorityCandidates: RiskCandidateSummary[]
  signalTrends: SignalSummary[]
  sourceHealth: SourceHealth[]
  pipeline: PipelineStageSummary[]
  customerAggregates: CustomerSignalAggregate[]
  policyChanges: PolicyChangeSummary[]
}
```

각 데이터 응답은 기존 `ApiEnvelope<T>`의 `generatedAt`, `sourceAsOf`, `schemaVersion`, `requestId`를 사용한다.

필수 공통 필드:

- 식별자
- 관측 기간
- 수집 시각
- 출처 또는 출처 ID
- 샘플/실제 구분
- 품질 상태
- 경고·보류 사유

운영 연결 전 필수 의존성:

1. 근거 수집·출처 계보 API
2. 후보 저장소와 상태·담당자·재검토일 API
3. 최소 집계된 고객 신호 API
4. SSO·RBAC 및 요청 ID·감사 로그

## 8. 화면 상태와 예외 처리

### 로딩

섹션별 skeleton을 사용하고 화면 전체를 빈 흰 화면으로 두지 않는다.

> 최근 데이터를 불러오는 중입니다. 이전 집계가 있으면 마지막 정상 시각을 함께 보여드립니다.

## 9. 접근성·반응형 기준

- 한 페이지에 `aria-current="page"`는 하나만 둔다.
- 클릭 가능한 카드도 실제 `button` 또는 `Link`로 제공한다.
- 차트는 요약 텍스트와 상세 표를 함께 제공한다.
- 상태는 색상과 함께 텍스트·아이콘으로 표현한다.
- 키보드로 탭, 행, 필터, 상세 링크를 모두 이동할 수 있어야 한다.
- 모바일에서는 KPI 1열, 후보 행을 카드로 전환하고 긴 표는 가로 스크롤을 허용한다.
- `prefers-reduced-motion` 환경에서는 차트 애니메이션을 생략한다.

## 10. 성공 기준

### MVP 완료 기준

- 첫 화면에서 기준 시각, 데이터 출처, 샘플/실제 여부를 확인할 수 있다.
- 신호·후보·집계 고객 신호가 서로 다른 엔터티로 구분된다.
- 우선 검토 후보에서 `/risks/:riskId`까지 한 번에 이동할 수 있다.
- 변화율과 절대량을 별도로 확인할 수 있다.
- 수집 지연·실패·빈 상태·부분 실패·권한 없음을 각각 처리한다.
- 고객 개인정보와 고객 원문이 대시보드에 노출되지 않는다.
- 자동 점수가 후보 확정이나 상품 확정으로 오해되지 않는다.
- 기존 `/risks`, `/risks/:riskId`, `/reports`, `/customer-insight`의 책임과 레이아웃을 침범하지 않는다.

### 검증 시나리오

1. 정상 데이터로 KPI, 후보, 추이, 채널 상태가 모두 표시된다.
2. 법령 채널만 실패해도 나머지 섹션이 표시되고 마지막 정상 시각이 보인다.
3. 후보가 0건일 때 숫자 `0`만 보여주지 않고 원인과 다음 행동을 안내한다.
4. 고객 신호가 단건일 때는 집계 큐에 노출하지 않는다.
5. 샘플 데이터가 실제 데이터처럼 보이지 않는다.
6. 모바일 폭에서 후보의 제목·상태·상세 링크를 읽고 조작할 수 있다.
7. 키보드만으로 필터와 후보 상세에 도달할 수 있다.

## 11. 구현 순서

1. 대시보드 전용 도메인 계약과 fixture 확정
2. 헤더·KPI·최신성 표기
3. 우선 검토 후보와 상세 링크
4. 신호 추이와 접근 가능한 표 대체 뷰
5. 채널 상태·부분 실패·오래된 데이터 처리
6. 파이프라인·고객 신호 집계·법령 변화 보조 패널
7. 반응형·키보드·샘플 표시 검증
8. `npm run check`와 대시보드 시나리오 QA

현재 구현의 `RiskDashboardPage`와 `RiskSignalPipeline`을 출발점으로 삼되, 중복된 KPI와 파이프라인 정보를 하나의 우선순위 체계로 정리한다. 대시보드 범위를 넘는 공통 계약 변경이 필요하면 먼저 `develop-footprint/platform/integration-contracts.md`에 변경안을 기록한다.
