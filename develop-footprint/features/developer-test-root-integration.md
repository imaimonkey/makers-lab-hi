# 개발자 테스트 워크벤치 루트 통합

## 통합 범위

`origin/0721-pivot-hyoje`의 실제 개발자 기능인 `/developer-test` 수직 슬라이스를 루트에 흡수했다. 브랜치의 네 방 데모 구조는 루트 내비게이션이나 라우팅에 연결하지 않는다.

- LLM util-0~4 선택 및 util별 Markdown 시스템 프롬프트
- 시스템 프롬프트와 사용자 테스트 입력의 분리 실행
- PDF, Word, PowerPoint, Excel, 텍스트, 이미지의 브라우저 내 컨텍스트 추출
- 공유 프롬프트 저장본의 읽기·수정·복원 상태
- util-1의 네이버 뉴스 검색어 관리, 단건 검색, 다중 키워드 수집
- 구조화 뉴스의 AI 분류·위험 묶음 저장과 저장 데이터 확인
- util-0 결과의 개발용 XLSX 저장

## 루트 연결

- 라우트: `/developer-test`
- 진입: 상단 사용자 모드 메뉴의 `개발자 (AI 테스트 모드)`
- 화면 셸: 기존 `RootLayout`을 사용하되 개발자 모드에서 업무용 사이드바를 숨긴다.
- 기존 안정 경로 `/`, `/risks`, `/risks/:riskId`, `/reports`, `/customer-insight`는 변경하지 않는다.

## 서버 경계

`vite.config.ts`의 개발 프록시가 공유 시스템 프롬프트, 네이버 뉴스 검색·수집, 뉴스 분류 저장, util-0 XLSX 저장, Gemini 호출을 처리한다. 브라우저에는 API 인증값을 저장하지 않으며, 기본 실행은 Mock 모드다. 실제 Gemini 호출과 네이버 호출은 개발 환경 변수 및 사용자가 현재 화면에 입력한 인증값이 있을 때만 수행한다.

개발 저장 데이터는 `data/` 아래에 생성되며 Git에 포함하지 않는다. 운영 전환에는 인증·권한, DB, 감사 이력, 버전 충돌 제어가 필요하다.

## 검증

- `npm run check` 통과
- 로딩·빈 결과·API 오류·파일 파싱 오류·저장 오류 메시지 제공
- 샘플/Mock 결과와 운영 승격을 분리하고, 수동 입력 저장은 위험 묶음으로 자동 승격하지 않음
