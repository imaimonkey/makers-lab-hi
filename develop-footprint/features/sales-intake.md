# 영업부서 현장 리포트 모드

`/sales-intake`는 영업부서에서 정리한 반복 고객 질문, 산업·기술 변화, 상품 개발 아이디어를 신규위험 검토의 출발점으로 남기는 별도 내부 모드다. 현재 1~4 실무자 화면에 대시보드나 목록을 추가하지 않고, 발표에서 입력 → 접수 → 추후 통합 경계를 보여주는 프레임만 제공한다. 표현과 레이아웃은 개인 고객 웹이 아니라 보험상품개발 실무 워크벤치와 같은 내부 업무 테마를 사용한다.

## 현재 흐름

1. 우상단 `영업부서` 모드로 전환한다.
2. `현장 리포트` 또는 `상품 개발 제안`을 선택한다.
3. 영업 채널, 제안 제목, 관찰한 위험·고객 반응, 제안 내용을 입력한다.
4. 필요한 후속 경로를 선택하고 접수한다.
5. 접수 ID와 검토 대기 상태를 확인한다. 최근 접수는 같은 브라우저에서만 보인다.

## 코드 소유권

- 셸: `src/app/layouts/SalesLayout.tsx`
- 경로 조합: `src/pages/sales-intake/SalesIntakePage.tsx`
- 입력·검증·최근 접수 UI: `src/features/sales-intake/SalesIntakeStudio.tsx`
- 도메인 타입·저장 어댑터: `src/domain/sales/salesIntake.ts`
- 모드 전환: `src/shared/components/ModeSwitch.tsx`

## 데모 상태와 제한

- 저장 키는 `hi-risk-studio.sales-intake.v1`이며 최대 30건을 `localStorage`에 저장한다.
- 운영 접수 API, SSO·RBAC, 담당자 배정, 첨부파일, 알림은 연결하지 않았다.
- 고객 이름, 연락처, 계약번호, 상세 주소, 상담 원문을 입력하지 않도록 안내한다. 브라우저 입력만으로 개인정보 유입을 완전히 방지할 수 없으므로 운영 전환 때 서버 재검사와 보존정책이 필요하다.
- 접수 하나는 신규위험 후보로 자동 승격되지 않는다. 최소 집계, 중복 확인, 근거 보강, 사람의 검토 후 후보 ID를 연결한다.

## 다음 통합 계약

운영화할 때 `SalesIntakeSubmission`에 API 요청 ID, 제출자 역할, 검토 상태 이력, 근거 참조 ID를 추가한다. 후보·평가·리포트 팀과 통합할 때는 접수 ID를 외래 참조로 사용하고 `RiskCandidateContract`를 복제하지 않는다. 영업 채널별 접근권한과 감사 로그를 먼저 합의한다.
