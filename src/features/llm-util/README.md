# LLM utilities

Gemini API를 활용하는 LLM 기능을 기능 단위로 분리해 관리하는 영역입니다. 개발자 테스트 화면에서는 사용자 메시지와 시스템 프롬프트를 별도로 실험합니다.

## 디렉터리 규칙

- `util-1/` ~ `util-4/`: 팀원별 또는 기능별 독립 작업 영역
- 각 util의 `system-prompt.md`에 해당 AI의 기본 역할·출력 형식·제한을 둡니다.
- 각 util의 `systemPrompt.ts`는 해당 Markdown을 읽어 실행 계약에 연결합니다.
- 각 util의 `index.ts`는 해당 작업 영역의 진입점이며, `runUtilN()` 호출은 해당 폴더의 Markdown 시스템 프롬프트를 자동으로 사용합니다.
- 공통 호출·Mock·Gemini 응답 계약은 이 디렉터리의 루트 모듈에서 관리합니다.
- util 간 공통 코드가 필요해지는 시점에 별도 공통 모듈 위치와 의존 방향을 합의합니다.
- API 키와 기타 비밀값은 저장소에 커밋하지 않습니다.

## 시스템 프롬프트 저장

- 폴더의 기본 시스템 프롬프트는 `util-1/system-prompt.md` ~ `util-4/system-prompt.md`에 각각 저장합니다.
- 개발자 모드(`/developer-test`)에서 AI별 시스템 프롬프트를 편집하고 공유 서버 저장소에 저장합니다.
- 저장된 값은 같은 서버에 연결된 다른 브라우저와 원래 `runUtilN()` 호출에서 함께 사용됩니다.
- `저장` 버튼은 서버 API를 통해 `data/llm-system-prompts.json`에 기록하고, `공유본 복원`은 현재 서버 저장본을 다시 불러옵니다.
- `system-prompt.md`는 공유 저장소가 비어 있을 때 사용하는 기본값·버전 관리용 원본입니다.
- 현재 개발 서버 저장소는 단일 JSON 파일이며, 운영에서는 인증·RBAC·DB·감사 이력이 있는 서버 API로 교체해야 합니다.

## util-1 네이버 뉴스 검색

- 개발자 화면에서 util-1을 선택하면 네이버 Client ID·Client Secret과 저장된 검색어를 사용해 뉴스를 검색할 수 있습니다.
- `뉴스 검색`은 선택한 검색어 1개를 조회하고, `정보 수집`은 저장된 검색어 전체를 조회해 중복 기사를 제거합니다.
- 인증값은 화면 상태로만 유지하고 `data/`나 Markdown에 저장하지 않습니다.
- 검색 결과는 `AI 1 입력에 넣기`로 사용자 테스트 입력에 전달한 뒤 1번 AI를 실행합니다.
- 네이버 API 호출은 브라우저가 아니라 Vite 개발 서버 프록시에서 수행합니다.
- 분류·저장의 기준은 네이버 응답을 코드가 만든 `NewsSourceRecord`입니다. AI가 반환한 `source_items`는 원문을 덮어쓰는 데 사용하지 않고, AI 위험 묶음의 `source_ids`가 입력 구조화 뉴스의 ID를 참조하는지 확인한 뒤 저장합니다.
- 기능 1번의 `수동 입력 결과 저장`은 테스트 입력·시스템 프롬프트·AI 응답만 `data/news-manual-test-runs.json`에 저장하며 위험 묶음을 만들지 않습니다. `자동 AI 분류·묶음 저장`은 구조화 뉴스와 위험 묶음을 `data/news-classifications.json`에 저장합니다.

## 다른 PC에서 공유 사용

호스트 PC에서 `npm run dev:shared`를 실행한 뒤 같은 네트워크의 다른 PC가 호스트 IP의 `/developer-test` 경로로 접속하면 동일한 `data/llm-system-prompts.json`을 읽고 저장합니다.

현재 개발 저장 API에는 로그인·권한·감사 로그가 없습니다. 신뢰할 수 없는 네트워크에 공개하지 말고, 운영 배포 전에는 인증된 서버 API와 DB 저장소로 교체해야 합니다.

개발자 모드의 `테스트 입력`은 시스템 프롬프트가 처리할 이번 실행의 사용자 메시지입니다. 기본값은 Mock이며, 실제 Gemini 호출은 서버 전용 개발 프록시를 사용합니다.
